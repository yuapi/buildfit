# 호환성 규칙 명세 (Phase 0)

`pc-builder-spec.md` §4.1의 필수 규칙 8개를 구현 가능한 수준으로 확정한 문서다.
**규칙 엔진을 구현하기 전에 이 문서를 읽는다** (CLAUDE.md 작업 규칙 1).

- 상위 문서: `pc-builder-spec.md` §4 (규칙 목록·판정 등급)
- 근거 조사: `docs/research/opendb-schema-analysis.md`
- 관련 ADR: ADR-0002 (OpenDB 1차 소스), ADR-0009 (판정 불가 등급)

> 필드 경로는 전부 **BuildCores OpenDB 스키마 기준**이다 (clone 커밋 `4880970`).
> 자체 DB 스키마(`pc-builder-spec.md` §5.8)로 적재한 뒤에는 `part_specs`의 key로
> 대응되며, 그 매핑은 적재 스크립트(이슈 #3)가 정의한다.

## 0. 공통 규약

### 0.1 판정 결과는 3값이다

ADR-0009에 따라 규칙 하나의 평가 결과는 boolean이 아니다.

```
pass     조건을 만족한다
fail     조건을 위반한다        → 등급은 규칙별로 오류 / 경고
unknown  판정에 필요한 데이터가 없거나 신뢰할 수 없다  → 판정 불가
```

`unknown`에는 **어느 부품의 어느 필드 때문인지**가 실려야 한다. 화면에도 그대로 나간다.

```
unknown:
  rule: 6
  missing: [{ part: "NZXT H5 Flow", field: "케이스 지원 PSU 폼팩터" }]
```

### 0.2 `unknown` 판정 조건은 세 가지다

| 유형 | 정의 | 예 |
|---|---|---|
| **결측** | 필드가 `null`이거나 빈 배열·빈 문자열 | 케이스 `supported_power_supply_form_factors: null` |
| **모순** | 값은 있으나 다른 필드와 물리적으로 양립 불가 | GPU `tdp: 575` + 커넥터 전부 `0` (§8.4) |
| **범위 밖** | 값이 스키마 enum이나 상식 범위를 벗어남 | `releaseYear: 20117` |

**결측만 검사하면 안 된다.** OpenDB에는 미입력을 `0`으로 채운 레코드가 실재하며,
`0`은 결측 검사를 통과해 **거짓 pass를 만든다.** 이것이 이 도구의 최악의 실패 모드다.

### 0.3 다투어지는 값은 `unknown`이 아니다 (ADR-0021)

값이 **없는** 것과 값이 **다투어지는** 것은 다르다.

`part_specs.disputed`는 두 곳에서 선다 — 사용자 오류 신고(§5.5)와, 같은 제품의
중복 레코드끼리 값이 어긋난 경우(이슈 #11)다. 그 값으로도 규칙은 답을 낼 수 있다.
**판정은 그대로 두고 근거의 상태를 결과에 덧붙인다** (`RuleResult.contested`).

```
✗ 오류  CPU 소켓(sTR4)과 메인보드 소켓(AM4)이 다릅니다. 장착되지 않습니다.
        검증 중인 값으로 판정했습니다: AMD Ryzen Threadripper 2950X의 소켓
```

`unknown`으로 내리지 않는 이유는 **신고 하나가 그 부품의 판정을 전부 지우는 셈이
되기 때문이다.** 그러면 신고가 무기가 된다.

표시는 **규칙이 붙이지 않는다.** 규칙↔필드 대응은 `SPEC_REQUIREMENTS`가 이미 단일
진실 소스로 들고 있으므로, 판정이 끝난 뒤 `evaluate()`가 한 곳에서 붙인다. 규칙
규칙마다 손을 대면 하나를 빠뜨리게 되고, 빠진 규칙은 조용히 확정적인 판정을 낸다.

보조 필드(`optional`)도 센다. 판정 불가를 만들지 않을 뿐 답에는 영향을 준다.

### 0.4 적용 순서

규칙 간 의존이 없으므로 순서는 자유다. 단 **화면 표시 순서는 번호순**으로 고정해,
같은 견적에 대해 항상 같은 순서로 보이게 한다.

## 1. CPU 소켓 = 메인보드 소켓

| | |
|---|---|
| **등급** | 오류 |
| **입력** | `CPU.socket` · `Motherboard.socket` |
| **충전율** | 100% / 100% (현행 세대) |

```
pass     같은 소켓 (아래 §1.1의 등가 표기 포함)
fail     그 외
unknown  둘 중 하나라도 결측
```

### 1.1 ★ 같은 소켓을 다르게 적은 것이 있다 (이슈 #16, 2026-09-22 고침)

전에 여기 「**함정 없음.** 두 필드가 같은 enum 51개 값 집합을 공유하므로 정규화
없이 문자열 완전 일치로 판정한다. 매핑표를 만들지 않는다」고 적었다. **전제가
틀렸다.** 값 집합을 공유하는 것은 맞는데, **그 안에 `TR4`와 `sTR4`가 둘 다
있고** CPU는 하나를, 보드는 다른 하나를 골랐다.

| 쪽 | 표기 | 개수 |
|---|---|---|
| CPU | `sTR4` | 10개 전부 (Threadripper 1900X ~ 2990WX) |
| 메인보드 | `TR4` | 23개 전부 (AMD X399) |

문자열로 비교하면 **230조합 전부 오류**였다. 고르기도 같은 비교를 써서 X399
보드를 고르면 맞는 CPU가 숨었다 (후보 1 · 숨김 31).

**거짓 통과가 이 도구의 가장 나쁜 결과다.** 그래서 확실한 것만 묶는다.

| 표기 쌍 | 묶는가 | 근거 |
|---|---|---|
| `TR4` ≡ `sTR4` | ✅ | TR4 보드 23개가 **전부 X399**, sTR4 CPU 10개가 **전부 X399용**. AMD 공식 명칭이 sTR4다 |
| `LGA 2011-3 Narrow` ≈ `LGA 2011-3` | ❌ | 7개 중 6개가 **C612 서버 칩셋**이다. 묶으면 데스크톱 Core i7이 서버 보드에서 통과한다 |
| `2 x LGA 2011` ≈ `LGA 2011` 등 | ❌ | 듀얼 소켓 보드는 2P 지원 Xeon만 받는다. 같은 이유다 |
| `LGA 1151` ≈ `LGA 1151v2` | ❌ | 핀은 같아도 **지원하는 CPU 세대가 다르다** (100/200 대 300 시리즈) |

묶지 않는 쪽은 **오류로 남는다.** 과하게 막는 것이 거짓으로 통과시키는 것보다
낫다. 칩셋까지 보는 판정은 소켓 규칙의 일이 아니다.

등가 표는 `packages/compat/src/sockets.ts` 한 곳에 있고, **규칙 1과 고르기 제약이
같은 표를 쓴다.** 둘이 갈라지면 "고를 땐 나오는데 판정은 오류"가 된다 (ADR-0010).
새 쌍을 넣을 때는 위 표처럼 **양쪽 부품을 전수로 확인한 근거**를 함께 적는다.

### 1.2 다른 규칙에도 같은 일이 있는가 — 전수 확인 (2026-09-22)

두 부품의 문자열을 맞대는 규칙마다, **한쪽에만 나타나는 값**을 뽑았다.
TR4/sTR4가 정확히 그런 모양이었다 (CPU에만 `sTR4`, 보드에만 `TR4`).

| 규칙 | 한쪽에만 있는 값 | 판단 |
|---|---|---|
| 2 메모리 규격 | `DDR1` (램 2) | 정말 없다 — DDR1 보드가 카탈로그에 없다 |
| 2 보조 (CPU 지원) | `DDR1`·`DDR2` (램) | 정말 없다 |
| 5 보드 폼팩터 | `DTX` (케이스 5) | 정말 없다 — DTX 보드가 없다 |
| 5 | `HPTX` (보드 3) | 정말 없다 — HPTX를 받는다고 적은 케이스가 없다 |
| 5 | `Thin Mini-ITX` (보드 5) | **호환 관계일 수 있다** — 아래 |
| 6 PSU 폼팩터 | `ATX/EPS` (파워 3) | **호환 관계일 수 있다** — 아래 |
| 6 | `TFX` (26) · `Mini-ITX` (12) (파워) | 정말 없다 — 그 파워를 받는다고 적은 케이스가 없다 |

**표기만 다른 같은 값은 없었다.** TR4/sTR4가 유일하다.

`Thin Mini-ITX` 보드는 Mini-ITX 케이스에, `ATX/EPS` 파워는 ATX 케이스에 들어간다고
**알려져 있다.** 그런데 TR4/sTR4와 달리 **데이터 자체로는 증명되지 않는다** — 그건
표기가 아니라 호환 관계이고, 이 환경에서는 근거 문서를 열 수 없다. 그래서 묶지
않는다. 영향은 보드 5개·파워 3개이고 판정은 오류로 남는다.

#### 쿨러 지원 소켓 — 규칙이 생기면 걸릴 것

쿨러 소켓을 보는 규칙은 아직 없다. 그 규칙을 만들 때 걸릴 것을 미리 적는다.
CPU·보드 어느 쪽에도 없는 쿨러 표기:

| 표기 | 쿨러 | 판단 |
|---|---|---|
| **`LGA 115`** | **11** | **잘린 표기로 보인다.** 쿨러가 흔히 적는 `LGA 115x`(1150/1151/1155/1156)의 `x`가 떨어졌다. 그대로 두면 이 11개가 맞는 보드와 **안 맞는다고** 나온다 |
| `LGA 1121` | 2 | 알려진 소켓이 아니다. 오타일 수 있다 |
| `SP3`·`SP5`·`SP6`·`sWRX8`·`LGA 4677`·`LGA 4710` | 각 1~7 | 서버·워크스테이션 소켓. 카탈로그에 그 CPU가 없다 |
| `LGA 1954` | 5 | 차세대 소켓. 카탈로그에 아직 CPU가 없다 |

쿨러도 `TR4` 22 · `sTR4` 277로 두 표기를 섞어 쓴다 — `sockets.ts`의 표가 그대로
쓰인다.

> 메시지 — fail: "CPU 소켓(AM5)과 메인보드 소켓(LGA1700)이 다릅니다. 장착되지 않습니다."

## 2. 메모리 규격 일치

| | |
|---|---|
| **등급** | 오류 |
| **입력** | `RAM.ram_type` · `Motherboard.memory.ram_type` · `CPU.specifications.memory.types[]` |
| **충전율** | 100% / 100% / 100% (현행 세대) |

```
pass     RAM.ram_type == Motherboard.memory.ram_type
         AND RAM.ram_type ∈ CPU.specifications.memory.types
fail     그 외
unknown  RAM 또는 메인보드 값이 결측
```

**CPU 쪽은 보조 검사다.** `CPU...memory.types`가 결측이면(전체 10.8%) 그 항목만 건너뛰고
메모리↔메인보드 일치만으로 판정한다. CPU 결측 하나로 전체를 `unknown`으로 만들지 않는다.
단 **건너뛰었다는 사실을 결과에 남긴다.**

> 메시지 — fail: "이 메모리는 DDR4인데 메인보드는 DDR5만 지원합니다."

## 3. 메모리 모듈 수 ≤ 슬롯 수

| | |
|---|---|
| **등급** | 오류 |
| **입력** | `RAM.modules.quantity` · `Motherboard.memory.slots` |
| **충전율** | 100% / 100% (현행 세대) |

```
pass     Σ(선택한 키트별 modules.quantity) <= Motherboard.memory.slots
fail     그 외
unknown  둘 중 하나라도 결측
```

**여러 키트를 담을 수 있으므로 합산이다.** 스펙 §3의 MVP는 메모리 1종 선택이지만,
엔진은 처음부터 합산 구조로 만든다. 나중에 키트 2개 선택을 허용할 때 규칙을 다시
쓰지 않아도 된다.

**함께 낼 정보 (등급: 정보)**: 모듈 수가 슬롯 수보다 적고 홀수가 아니면
"듀얼 채널로 동작하려면 2의 배수로 채우는 것이 좋습니다" 수준의 안내. 판정은 아니다.

## 4. GPU 길이 ≤ 케이스 GPU 최대 길이

| | |
|---|---|
| **등급** | 오류 (여유 구간은 경고) |
| **입력** | `GPU.length` · `PCCase.max_video_card_length` (둘 다 mm) |
| **충전율** | 100% / 97.4% (현행 세대) |

```
pass     GPU.length <= max * 0.95
경고     max * 0.95 < GPU.length <= max
fail     GPU.length > max
unknown  둘 중 하나라도 결측
```

**95% 임계는 스펙 §5.1의 결정이다.** 제조사 표기가 낙관적이어서 전면 팬이나 케이블
때문에 표기값 그대로는 안 들어가는 경우가 많다.

> 메시지 — 경고: "GPU 길이 336mm, 케이스 한계 340mm입니다. 빠듯할 수 있고 전면 팬이나
> 케이블 정리에 따라 안 들어갈 수 있습니다."

### 4.1 칩만 선택한 경우

AIB 모델을 지정하지 않으면 이 규칙은 **`unknown`**이고, 대신 범위만 안내한다.
단정하지 않는다 (`pc-builder-spec.md` §5.1).

**범위는 OpenDB에서 계산해 쓴다.** chipset별 AIB `length` 분포의 min~max를 적재 시
집계해 두면 된다. 실제 분포를 확인해보면 범위 안내가 왜 필요한지 분명하다.

| chipset | AIB 수 | 최소 | 중앙값 | 최대 | 스프레드 |
|---|---|---|---|---|---|
| RTX 5060 | 72 | 145mm | 228mm | 329mm | **184mm** |
| RTX 4060 Ti 8GB | 53 | 170mm | 250mm | 338mm | 168mm |
| RTX 5080 | 77 | 220mm | 329mm | 385mm | 165mm |
| RTX 4090 | 61 | 203mm | 336mm | 360mm | 157mm |
| RTX 4070 | 86 | 201mm | 300mm | 342mm | 141mm |
| RTX 4070 SUPER | 59 | 227mm | 269mm | 342mm | 115mm |

스펙 §5.1이 "같은 4070이라도 240mm에서 340mm까지 벌어진다"고 한 관찰은 정확했고,
실제로는 **더 넓다**(201~342mm). 칩만으로 길이를 판정할 수 없다는 근거다.

> 메시지 — unknown: "RTX 4070은 모델에 따라 201~342mm로 차이가 큽니다.
> 정확한 판정을 위해 구체적인 모델을 선택하거나 길이를 직접 입력해 주세요."

AIB를 고르면 §4의 확정값 판정으로 넘어간다.

## 5. 메인보드 폼팩터 ⊂ 케이스 지원 목록

| | |
|---|---|
| **등급** | 오류 |
| **입력** | `Motherboard.form_factor` · `PCCase.supported_motherboard_form_factors[]` |
| **충전율** | 100% / 100% (현행 세대) |

```
pass     Motherboard.form_factor ∈ PCCase.supported_motherboard_form_factors
fail     그 외
unknown  둘 중 하나라도 결측
```

**정규화 불필요.** 두 enum이 정확히 같은 12개 값이다 — 조사에서 대조 확인했다.

```
ATX, Micro ATX, Mini-ITX, EATX, Mini DTX, DTX,
SSI EEB, SSI CEB, XL ATX, HPTX, Thin Mini-ITX, Flex ATX
```

**주의: `PCCase.form_factor`와 혼동하지 않는다.** 그건 케이스 자체의 분류
(`ATX Mid Tower` 등 17개 값)이고, 판정에 쓰는 것은
`supported_motherboard_form_factors` 배열이다.

**하위 호환을 임의로 가정하지 않는다.** ATX 케이스가 대체로 Micro ATX를 수용하지만,
그건 `supported_motherboard_form_factors`에 실제로 들어 있을 때만 참이다. 배열에
없으면 `fail`이다. 추론으로 통과시키지 않는다.

## 6. PSU 폼팩터 ⊂ 케이스 지원 ★ 데이터가 가장 부족한 규칙

| | |
|---|---|
| **등급** | 오류 |
| **입력** | `PSU.form_factor` · `PCCase.supported_power_supply_form_factors[]` |
| **충전율** | 100% / **16.8%** (현행 세대) ← **83.2% 결측** |

```
pass     PSU.form_factor ∈ PCCase.supported_power_supply_form_factors
fail     그 외
unknown  케이스 쪽 결측 (현행 세대 케이스의 83.2%)
```

enum은 양쪽 7개 값이 정확히 일치한다: `ATX, SFX, SFX-L, TFX, Flex ATX, Mini-ITX, ATX/EPS`

**Phase 0 초기에는 이 규칙이 대부분 `unknown`으로 뜬다.** 정상 동작이다.
케이스 보강(이슈 #6 어드민)이 진행될수록 줄어든다.

**절대 하지 말 것**: 케이스가 ATX 보드를 지원한다는 이유로 ATX PSU도 지원한다고
추론하기. 상관관계는 높지만 SFX 전용 케이스가 실재하고, 틀리면 사용자가 못 쓰는
파워를 산다.

> 메시지 — unknown: "이 케이스가 지원하는 파워 규격 정보가 아직 없어 판정하지
> 못했습니다. 제조사 스펙을 직접 확인해 주세요." + 보강 요청 버튼

### 6.1 판정 불가에 덧붙이는 참고 분포 (ADR-0013)

판정은 `unknown` 그대로 두되, 같은 `form_factor`에서 **관측된** 지원 분포를
`notes` 한 줄로 덧붙인다. 판정을 바꾸지 않으므로 거짓 통과가 생기지 않는다.

> 참고: BuildCores OpenDB PCCase 전수 3,782건에서 Mini ITX Tower 중 값이 확인된
> 17건은 SFX 14건(82%), SFX-L 14건(82%), ATX 2건(12%), Flex ATX 1건(6%)이었습니다.
> 이 케이스의 사양이 아니라 같은 폼팩터의 관측 분포입니다 (측정일 2026-09-19).

- 분포표: `packages/compat/src/case-reference.ts` — 정적 상수. 엔진은 DB를 쓰지 않는다
- 측정 근거와 재현 절차: `docs/research/case-psu-formfactor-distribution.md`
- **표본 10건 미만은 인용하지 않는다.** 4건의 100%가 401건의 99%보다 세 보이는
  착시를 만들지 않는다. 데이터가 0건인 폼팩터(HTPC·Desktop·테스트벤치)도 같다
- 해당 케이스의 값이 채워지면 이 문장은 자동으로 사라진다

이 패턴은 규칙 6에만 쓴다. 다른 규칙으로 넓히려면 그때 근거를 따로 만든다.

## 7. 소비전력 대비 PSU 정격 — 구간 판정

| | |
|---|---|
| **등급** | 오류 / 경고 (구간에 따라) |
| **입력** | `CPU.specifications.tdp`·`ppt` · `GPU.tdp` · `PSU.wattage` + **범위 가정** |
| **충전율** | 100% / 100% / 100% (현행 세대) |

### 7.1 메인보드 소비전력 필드는 존재하지 않는다

`pc-builder-spec.md` §4.1이 필요 데이터로 적었던 "보드 파워"는 **OpenDB 메인보드
스키마에 없다.** `tdp` / `wattage` / `power_draw`를 전부 검색해 확인했다.
`power_connectors`는 커넥터 종류(`24-pin`)일 뿐 W가 아니다.

따라서 **CPU와 GPU만 실측값을 쓰고 나머지는 가정한다.**

```
CPU 전력 = specifications.ppt 가 있으면 ppt, 없으면 tdp
GPU 전력 = tdp
```

`ppt`를 우선하는 이유는 그것이 실측 최대에 가깝고 TDP가 실사용 피크를 과소평가하기
때문이다 (현행 세대 CPU 98.3% 충전).

### 7.2 가정은 점 값이 아니라 범위다 ★

공개 자료의 편차가 크다 — 메인보드는 **25~80W로 3배 차이**다. 점 값을 하나 고르는
것은 근거 없는 수치를 만드는 것이고, 이 규칙은 오류 등급이라 틀리면 사용자가 멀쩡한
파워를 못 쓴다고 판단하거나 부족한 파워를 괜찮다고 믿는다.

ADR-0004·§6.6.4의 원칙을 그대로 적용한다 — **단일 수치를 내놓지 않는다.**

| 항목 | 범위 | 출처 |
|---|---|---|
| 메인보드 | 25 ~ 80 W | Seasonic PSU 계산기 가이드 — "Consumes roughly 25 to 80 watts" |
| 메모리 (모듈당) | 2 ~ 5 W | 〃 — "Draws about 2 to 5 watts per module" |
| 드라이브 (개당) | **0 ~ 15 W** | 〃 — "you can put up to 15W, especially for some HDDs" (이슈 #5) |
| 수랭 쿨러 (AIO) | **15 ~ 30 W** | 〃 — "Water cooling (AIO) can draw 15–30 W" (이슈 #30) |
| 공랭 쿨러 팬 (개당) | **1 ~ 3 W**, 조명이 있거나 모르면 **1 ~ 6 W** | 〃 — "Conventional fans consume 1–3 W each, with backlighting – up to 6 W" (이슈 #30) |
| 여유분 배수 | 1.3 | `pc-builder-spec.md` §4.1. Seasonic의 20~30%와 일치 |

**원문 확인 (2026-09-24).** 전에는 이 실행 환경이 `seasonic.com`을 막아 「원문 미확인」으로
노출했다. 지금도 Cloudflare가 막지만 **웹 아카이브의 2025-07-11 사본**에서 위 문장을 그대로
확인했다. 경위와 사본 주소는 `docs/research/power-constants.md` §7.

**드라이브의 하한은 0이다.** 원문은 상한만 준다. 하한을 지어내지 않는다 — 최소 합계가
낮을수록 「가정을 가장 낮게 잡아도 부족」(오류)이 덜 나므로 이쪽이 안전하다.

**CPU 쿨러 (이슈 #30).**

```
수랭(water_cooled)                    15 ~ 30 W
공랭, fanless 또는 팬 0개              0 W
공랭, 팬 수를 앎                       팬 수 × 1~3 W   (조명 목록이 정확히 ["None"]일 때)
                                       팬 수 × 1~6 W   (조명이 있거나, 목록이 비어 모를 때)
공랭, 팬 수를 모름 / 수랭 여부를 모름  넣지 않고, 넣지 않았다고 적는다 (§7.4.1)
```

- **팬 수를 지어내지 않는다.** 원본의 `fan_quantity`가 86%(2,074/2,405) 비어 있다. 「공랭은 보통
  팬 한두 개」 같은 수를 넣으면 근거 없는 수치가 된다
- **조명이 확실하지 않으면 넓은 쪽이다.** 빈 목록 `[]`(82%)은 조명이 없다는 뜻인지 모른다.
  최대를 넉넉히 잡는 쪽이 「여유 있음」을 잘못 말하지 않는다
- 케이스 팬·커스텀 수랭은 견적에 없어 가정하지 않는다

### 7.3 판정식

```
모듈수   = Σ(선택한 키트별 module_count)
총_최소  = CPU + GPU + 보드_최소 + 메모리_최소 × 모듈수
총_최대  = CPU + GPU + 보드_최대 + 메모리_최대 × 모듈수
권장정격 = ceil(총_최대 × 1.3)

pass     PSU.wattage >= 권장정격                    여유 있음
경고     총_최소 <= PSU.wattage < 권장정격          가정에 따라 갈림
fail     PSU.wattage < 총_최소                      가정을 아무리 낮게 잡아도 부족
unknown  CPU/GPU 전력 또는 PSU 정격 결측
```

- GPU를 고르지 않았으면 GPU 전력은 0이다 (내장그래픽 구성)
- 메모리를 고르지 않았으면 모듈수는 0이다
- **경계 구간이 넓은 것은 결함이 아니다.** 가정 범위가 좁혀지면 경고 구간도 줄어든다

### 7.4 표시 원칙

**가정 범위와 출처를 결과에 함께 낸다.** 원문을 확인하지 못한 가정이 생기면 그 상태도 숨기지 않는다.
사용자가 왜 그 판정이 나왔는지 확인할 수 있어야 한다.

> 메시지 — 경고: "총 소비전력 약 551~612W로 추정됩니다. 권장 정격은 796W인데
> 750W라 가정에 따라 갈립니다. (메인보드 25~80W, 메모리 모듈당 2~5W로 가정)"

#### 7.4.1 계산에서 빠진 부품을 말한다 ★

**스토리지는 견적에 담기지만 전력 계산에 들어가지 않는다.** NVMe·SATA의 유휴·피크
전력 범위를 출처와 함께 확보하지 못했고, 추정치를 지어내지 않는다 (이슈 #5).

조용히 빼면 사용자는 합계가 전부인 줄 안다. 그러면 **이 구간은 실제보다 낮다** —
그 방향까지 말한다.

> 부연: "드라이브 2개의 소비전력은 근거 있는 범위를 구하지 못해 계산에 넣지
> 않았습니다. 실제 소비전력은 이 구간보다 높습니다."

가정 설명보다 **앞에** 적는다. 가정이 틀렸다는 것보다 구간 자체가 낮다는 것이
먼저 알아야 할 사실이다.

전력 범위를 확보하면 이 부연이 사라지고 `POWER_ASSUMPTIONS`에 범위가 더해진다.
쿨러·팬도 같은 사정이다.

## 8. PCIe 보조전원 커넥터 수 충족 ★ 정규화와 모순 검사 필요

| | |
|---|---|
| **등급** | 오류 (16핀 변환 케이블 경우는 경고, §8.7) |
| **입력** | `GPU.power_connectors.*` · `PSU.connectors.*` |
| **충전율** | 96.7~100% / 100% (현행 세대) |

### 8.1 GPU와 PSU의 커넥터 표현이 비대칭이다

| 커넥터 | GPU 쪽 | PSU 쪽 |
|---|---|---|
| 6핀 | `pcie_6_pin` | `pcie_6_plus_2_pin` — 6핀·8핀 **통합 카운트** |
| 8핀 | `pcie_8_pin` | 위와 같은 필드 |
| 16핀 | `pcie_12VHPWR` **와** `pcie_12V_2x6` **분리** | `pcie_12vhpwr` **하나뿐** |

PSU의 6+2핀 커넥터는 6핀 요구와 8핀 요구 양쪽을 충족한다. GPU의 12VHPWR과 12V-2x6은
핀 배열이 호환되므로(ATX 3.0 vs 3.1) PSU 쪽에서는 구분하지 않는다.

### 8.2 정규화 후 판정식

```
GPU_8pin류  = (pcie_8_pin  ?? 0) + (pcie_6_pin ?? 0)
GPU_16pin류 = (pcie_12VHPWR ?? 0) + (pcie_12V_2x6 ?? 0)

pass     PSU.connectors.pcie_6_plus_2_pin >= GPU_8pin류
         AND PSU.connectors.pcie_12vhpwr  >= GPU_16pin류
fail     그 외
unknown  §8.3 또는 §8.4에 해당
```

### 8.3 결측 판정

GPU 커넥터 4필드 중 **하나라도 `null`이면 `unknown`**이다. 현행 세대 GPU의 43건이
부분 null이다. `null`을 0으로 간주하지 않는다 — 그러면 §8.4의 거짓 통과가 된다.

### 8.4 ★ 모순 검사 — `0`을 그대로 믿지 않는다

**조사에서 확인된 실제 데이터 문제다.** 적재 후 전수 집계한 결과는 처음 추정보다
훨씬 나쁘다.

| 범위 | 모순 건수 |
|---|---|
| RTX 40/50 (조사 시 표본) | 166 / 1,069 |
| **GPU 전체 (TDP > 75W)** | **705 / 3,468 = 20.3%** |

**TDP가 75W를 넘는 GPU 다섯 중 하나꼴로 커넥터가 전부 명시적 `0`이다.**
RTX 5090(TDP 575W)도 포함된다.

PCIe 슬롯이 공급할 수 있는 전력은 **75W**다. 그보다 많이 먹는 카드는 보조전원이
반드시 필요하므로, 이 조합은 **물리적으로 불가능하며 데이터 오류다.**

```
if GPU.tdp > 75 AND GPU_8pin류 == 0 AND GPU_16pin류 == 0:
    → unknown (사유: 커넥터 정보 오류로 판단됨)
```

**이 검사가 없으면 166건이 "보조전원 0개 필요 → 통과"로 처리된다.** 결측 검사만으로는
잡히지 않는다. 값이 `null`이 아니라 `0`이기 때문이다.

> 이 사례가 ADR-0009의 근거다. 결측을 통과로 처리하는 것뿐 아니라, **잘못된 값을
> 통과로 처리하는 것**도 막아야 한다.

### 8.5 알려진 소수 이상치

| 패턴 | 건수 | 처리 |
|---|---|---|
| `12VHPWR: 1` **그리고** `12V_2x6: 1` | 2 | 합산하면 16핀 2개를 요구하게 된다. 중복 기입 의심 → `unknown` |
| `12VHPWR: 2` | 1 | 소비자용 카드에 16핀 2개는 이례적 → `unknown` |

**보수적으로 `unknown`을 택한다.** 둘 다 극소수라 실사용 영향이 작고, 잘못 통과시키는
비용이 판정을 미루는 비용보다 크다.

### 8.6 ★ 파워 쪽 `0`도 그대로 믿지 않는다 (이슈 #29)

§8.4는 그래픽카드 쪽만 봤다. **파워 쪽에도 같은 문제가 있다.**

| 파워 용량 | 8핀·16핀 **둘 다 0** |
|---|---|
| 550~749W | 17.8% (184 / 1,035) |
| 750~999W | 26.9% (273 / 1,013) |
| 1000W+ | 25.8% (171 / 662) |

Corsair HX1500i, SeaSonic PRIME TX-850처럼 커넥터가 있는 것이 분명한 제품이다. **이름에
ATX 3.x가 붙은 파워 126개 중 56개가 둘 다 0**이다 — ATX 3.x는 16핀을 갖추는 규격이다.
이 값을 믿으면 「보조전원이 부족합니다」 **거짓 오류**가 난다. 무작위 견적 3,000개에서
규칙 8 오류의 가장 큰 몫이었다.

```
if 그래픽카드가 보조전원을 요구 AND PSU 8핀 == 0 AND PSU 16핀 == 0:
    → unknown (사유: 파워 커넥터 정보가 비어 있는 것으로 보임)
```

**용량으로 가르지 않는다.** 400W 미만은 76%가 둘 다 0이고 그중에는 정말 커넥터가 없는
파워도 있을 것이다. 하지만 어디부터 믿을지 정할 근거가 없다. 판정을 미루는 쪽이 거짓
오류보다 낫다 — 틀린 오류는 쓸 수 있는 파워를 버리게 만든다.

### 8.7 16핀이 모자라도 남는 8핀이 있으면 경고다 (이슈 #29)

**파워 쪽 16핀 `0`은 대체로 실제 값이다.** 8핀은 있고 16핀만 0인 2,050개 중 이름에 ATX 3.x가
붙은 것은 7개뿐이다 — 16핀 규격 이전의 파워다. 16핀 카드를 이런 파워에 쓰는 것은 흔하고,
**8핀 여러 개를 16핀 하나로 모으는 변환 케이블**로 연결한다. NVIDIA는 RTX 4090에 4갈래 변환
케이블을 동봉한다 ([igor'sLAB](https://www.igorslab.de/en/this-is-how-nvidias-4-fold-adapter-for-12vhpwr-connection-of-geforce-rtx-4090-works-with-workaround/)).

**통과로 올리지 않는다.** 모든 제조사가 동봉한다는 근거가 없고, 변환 케이블이 요구하는
8핀 수도 카드마다 다르다. 그래서 **확인하라는 경고**다.

```
16핀 부족 AND 8핀 요구는 충족 AND 남는 8핀 > 0    → warning  (변환 케이블·남는 8핀 수를 확인)
16핀 부족 AND 남는 8핀 = 0                          → error    (변환 케이블을 꽂을 곳이 없다)
```

남는 8핀이 몇 개면 충분한지는 말하지 않는다 — 카드마다 달라 근거 없는 수를 지어내게 된다.
남는 개수만 보여 준다.

## 9. CPU 쿨러 높이 ≤ 케이스 최대 높이 (Phase 1)

| | |
|---|---|
| **등급** | 경고 |
| **입력** | `CPUCooler.height` · `CPUCooler.water_cooled` · `PCCase.max_cpu_cooler_height` |
| **충전율** | 70.4% / 99.9% / **35.2%** |

명세: `pc-builder-spec.md` §4.2 규칙 9. **공랭에만 적용한다.**

```
skip     water_cooled = true       수랭은 높이가 아니라 라디에이터 문제다 (규칙 10, Phase 2)
pass     쿨러 높이 ≤ 케이스 한계
warning  쿨러 높이 > 케이스 한계
unknown  어느 한쪽 결측
```

### 9.1 오류가 아니라 경고인 이유

명세 §4.2가 이 규칙을 경고 등급에 둔다. 제조사가 재는 "최대 높이"는 사이드 패널까지의
여유를 얼마나 보수적으로 잡았는지에 따라 달라지고, 팬 위치를 옮기거나 패널을 바꿔
들어가는 사례가 실재한다. **오류로 단정하면 실제로는 쓸 수 있는 조합을 막는다.**

반대로 규칙 4(GPU 길이)는 오류다. GPU는 슬롯에 고정되므로 조정 여지가 없다.
같은 "길이 비교"지만 등급이 다른 이유가 이것이다.

### 9.2 수랭을 건너뛰되 건너뛴 사실은 남긴다

`water_cooled = true`면 이 규칙은 `RuleResult.skipped`에 사유를 남기고 판정하지
않는다. 통과로 표시하지 않는다 — 라디에이터가 들어가는지는 **아직 아무도 확인하지
않았다.** 규칙 10이 Phase 2 이후라 그 확인은 지금 불가능하다 (명세 §4.2).

`water_cooled`가 결측이면 수랭 여부를 모르므로 `unknown`이다. 높이가 있다고
공랭으로 단정하지 않는다 — AIO에도 `height`가 채워진 레코드가 있다.

### 9.3 여유 구간을 경고로 올리지 않는다

규칙 4는 95% 이상을 "빠듯함" 정보로 알린다. 여기서는 하지 않는다.
케이스 한계값 자체가 35.2%만 채워져 있고 보수성도 제각각이라, 그 위에
다시 5% 경계를 얹으면 근거 없는 정밀도를 주장하게 된다.

### 9.4 부품 슬롯 추가

이 규칙을 쓰려면 견적에 CPU 쿨러 슬롯이 생긴다. 따라오는 변경:

- 공유 코드 **v2** — 슬롯이 하나 늘어난다. **v1 디코더는 그대로 둔다** (ADR-0012)
- `localStorage` 저장 포맷에 `cooler` 필드 추가 — add-only (ADR-0005)

## 12. BIOS 업데이트 필요 여부 (Phase 1)

> **절 번호는 규칙 번호를 따른다.** §10(라디에이터)과 §11(메모리 높이 간섭)이
> 비어 있는 것은 아직 구현하지 않아서다. 번호를 당겨 메우지 않는다 —
> 명세 §4.2의 규칙 번호와 어긋나면 어느 쪽이 맞는지 매번 확인해야 한다.

| | |
|---|---|
| **등급** | 경고 / 정보 (Flashback 유무로 갈린다) |
| **입력** | `CPU.releaseYear` · `Motherboard.releaseYear` · `Motherboard.bios_features.flashback` · 보조: `Motherboard.socket` (§12.5) |
| **충전율** | 88.2% / **20.4%** / 99.3% |

명세 §4.2 규칙 12. **실제로 가장 많이 겪는 함정이다.** 보드는 맞는데 BIOS가
구버전이라 부팅이 안 되는 상황.

```
skip     CPU 연도 ≤ 보드 연도        보드가 더 나중이면 BIOS는 문제가 아니다
skip     보드 연도 결측, CPU 연도 ≤ 보드 소켓의 첫 CPU 연도   (§12.5)
warning  CPU 연도 > 보드 연도, Flashback 없음   CPU 없이 업데이트할 수 없다
info     CPU 연도 > 보드 연도, Flashback 있음   업데이트가 필요할 수 있다
unknown  어느 한쪽 연도 결측 (위 둘째 줄이 아니면)
```

### 12.1 연도 비교는 신호이지 증거가 아니다

같은 해에 나온 조합은 가려내지 못한다. 연 단위 데이터로 할 수 있는 최선이고,
1차 소스가 월·일을 주지 않는다 (§5.8). 그래서 **오류가 아니라 경고**다.
"부팅이 안 된다"가 아니라 "확인이 필요하다"로 말한다.

반대 방향도 단정하지 않는다. 보드가 CPU보다 나중에 나왔어도 그 보드 개체가
공장에서 구버전 BIOS를 달고 나왔을 수 있다. 다만 그 경우 **판매 시점의 보드는
대개 최신 BIOS**라 경고를 띄우면 대부분 헛경고가 된다. 신호가 약한 쪽에서는
말하지 않는 것을 택한다.

### 12.2 Flashback이 심각도를 가른다

Flashback이 없으면 BIOS를 올리는 데 **돌아가는 CPU가 필요한데, 그 CPU가
바로 지금 못 쓰는 CPU다.** 사용자는 구형 CPU를 따로 구해야 한다.
있으면 USB만으로 올라가므로 번거로울 뿐이다. 같은 상황이지만 사용자가
할 일이 완전히 다르므로 등급을 나눈다.

`flashback`이 결측이면(0.7%) 심각한 쪽으로 가정하지 않는다. 판정 불가다.

### 12.3 보드 연도 20.4%가 이 규칙의 한계다

명세는 "현행 세대에서도 40% 결측"으로 적었으나, 전수로는 **79.6%가 결측**이다.
그래서 대부분의 견적에서 이 규칙은 판정 불가로 뜬다. 정상 동작이다.
`/admin` 보강 대상이지만, 출시 연도는 제조사 페이지에도 잘 적혀 있지 않아
케이스 치수보다 채우기 어렵다.

### 12.4 소켓보다 앞선 연도는 「검증 중」으로 표시한다 (이슈 #18)

원본에는 소켓이 나오기 전 연도를 단 레코드가 있다 — Ryzen 5 7500F(AM5)가 2020년이다.
그 값으로 비교하면 헛경고가 나거나 경고를 놓친다. **판정은 원본 값으로 그대로
내고**(ADR-0021) 「검증 중인 값으로 판정했습니다」를 붙인다. 고르는 기준과 경계의
여유: `docs/research/release-year-plausibility.md`

### 12.5 보드 연도가 없어도 소켓 첫해 CPU는 판정한다 (이슈 #28)

**보드는 자기 소켓의 첫 CPU보다 먼저 나올 수 없다.** 그래서 그 소켓 CPU들의 가장 이른
출시 연도가 보드 연도의 **하한**이다. CPU 연도가 그 하한 이하이면 보드 연도를 몰라도
「보드가 CPU와 같거나 더 나중」이다 — 위 첫째 줄과 같은 결론이다.

```
하한 = min(CPU.releaseYear)   같은 소켓(sockets.ts 등가 포함) · 대표 레코드 · 「검증 중」 연도 제외
```

- **풀리는 것은 소켓 첫해에 나온 CPU뿐이다.** 하한이 그 소켓 CPU들의 최솟값이라,
  후속 세대(AM4에 라이젠 5000)는 여전히 보드 연도가 필요하다
- **가정을 데이터로 확인했다.** 연도가 알려진 보드 중 소켓 첫 CPU보다 앞선 것은 ASUS
  B650M-AYW 2건(AM5인데 2020년)뿐이고, 둘 다 §12.4가 이미 「검증 중」으로 세운 오류다
- **「검증 중」 CPU 연도는 하한에서 뺀다.** Ryzen 5 7500F(AM5, 2020년)를 넣으면 AM5의 하한이
  2020이 되어 아무것도 풀리지 않는다 — 틀린 쪽으로는 안 가지만 쓸모가 없어진다
- **`loadBuild` 한 곳에서 계산한다.** 서버 판정과 편집 중 판정이 같은 값을 쓴다
- 판정 불가(같은 소켓 조합, 2026-09-23): **83.2% → 67.8%** — 199,341건 중 36,813건이 풀린다

근거: 이슈 #28

## 15. GPU 두께(슬롯) ≤ 케이스 확장 슬롯 수 (Phase 1)

| | |
|---|---|
| **등급** | 오류 |
| **입력** | `GPU.total_slot_width` · `PCCase.expansion_slots` |
| **충전율** | **98.6% / 98.7%** |
| **판정 불가** | **3.04%** (전수 1,461만 조합) |

명세 §4.2 규칙 15. 두꺼운 GPU가 작은 케이스에 안 들어가는 것은 실제로 자주 겪는
실패인데 **규칙 목록에 빠져 있었다.** 규칙 4는 길이만 본다.

케이스가 얽힌 규칙 중 **지금 바로 거의 다 판정되는 유일한 규칙이다.** 규칙 6은
83%, 규칙 9는 75%가 판정 불가인데 이 규칙은 3%다.

```
필요 슬롯 = ceil(total_slot_width)

unknown  total_slot_width 결측 또는 1 미만 또는 5 초과   (§15.2)
unknown  expansion_slots 결측 또는 0 이하               (§15.2)
error    필요 슬롯 > expansion_slots
pass     그 외
```

### 15.1 ★ `case_expansion_slot_width`를 쓰지 않는다

GPU 스키마에는 이름부터 딱 맞는 필드가 따로 있다 — "The number of case expansion
slot widths the card occupies". **값이 틀렸다.**

두 필드가 다 있는 1,518건 중 **741건(48.8%)에서 이 값이 `total_slot_width`보다
작다.** 두께 2.5슬롯 카드가 확장 슬롯 2칸만 차지한다는 뜻이라 물리적으로 불가능하다.
같은 두께 2.5에 2 · 2.5 · 3 세 가지 답이 들어 있다 — 채운 사람마다 다르게 이해한
필드다.

커버리지도 40.4%로 `total_slot_width`의 98.6%보다 한참 낮다. 쓸 이유가 없다.

`ceil`을 쓰는 이유는 브래킷이 아니라 쿨러다. 2.5슬롯 카드는 브래킷이 2칸이어도
쿨러가 3번째 칸 자리를 먹는다.

`expansion_slots`는 항상 정수라서 `ceil(t) > s`는 `t > s`와 같다 — 전수에서
`t ≤ s < ceil(t)`인 조합은 **0건**이었다. 구현은 `ceil`을 그대로 쓴다.
정수가 아닌 값이 들어오는 날 식이 조용히 달라지지 않게 한다.

### 15.2 이상치를 판정하지 않는다

**GPU** — `total_slot_width`에 슬롯이 아니라 mm를 넣은 레코드가 4건 있다
(120 · 77 · 55.6 · 44). 정상 범위는 0.95~5이고, 5를 넘는 값은 전부 이 4건이다.
**1 미만이거나 5 초과면 판정하지 않는다.**

**케이스** — `expansion_slots = 0`이 9건이고 그중에 ATX 미드타워가 섞여 있다.
확장 슬롯이 없는 ATX 미드타워는 없다. §8.4의 「`0`을 그대로 믿지 않는다」와
같은 처리를 한다.

### 15.3 필요조건이지 충분조건이 아니다 ★

`expansion_slots`는 케이스 **뒷면 구멍의 총 개수**다. GPU가 실제로 꽂히는 자리는
메인보드의 x16 슬롯이 몇 번째 칸이냐에 달려 있고, 그 아래로 남는 칸은 총 개수보다
적을 수 있다.

이 규칙은 **GPU가 맨 위 칸에 꽂힌다고 가정한 낙관적 판정**이다.

- 넘으면 → 어떤 보드를 써도 안 들어간다. 오류로 단정해도 된다
- 통과하면 → 들어갈 **가능성**이 있다는 뜻이다

**통과 문구에 이 한계를 적는다.** "확인됨"으로 읽히면 안 된다. 라이저 케이블로
세로 장착하는 경우도 이 규칙 밖이다.

근거: `docs/research/gpu-slot-width.md`

## 16. 총 메모리 용량 ≤ 보드·CPU 최대 (Phase 1)

| | |
|---|---|
| **등급** | 경고 |
| **입력** | `RAM.capacity_gb` · `Motherboard.memory_max_gb` · `CPU.memory_max_gb` |
| **충전율** | **100% / 99.8% / 100%** |
| **판정 불가** | **0.27%** (전수 1,804만 조합) |

명세 §4.2 규칙 16. `memory_max_gb`가 양쪽에 적재돼 있고 부품 화면에 표시까지 되는데
**어떤 규칙도 쓰지 않았다.** 규칙 2는 규격을, 규칙 3은 모듈 수를 본다. 용량은
아무도 안 봤다.

```
한계 = min(보드 최대, CPU 최대)     CPU를 안 골랐으면 보드만

unknown  RAM 용량 결측
unknown  보드·CPU 최대가 둘 다 결측
unknown  보드 최대 < 보드 슬롯 수     (§16.2)
unknown  CPU 최대 ≤ 0               (§16.2)
warning  총 용량(킷 합계) > 한계
pass     그 외
```

### 16.1 CPU도 본다 — 14.2%에서 CPU가 더 낮다

소켓이 맞는 CPU × 보드 264,679 조합에서 **37,667건(14.2%)은 CPU의 최대가 보드보다
낮다.** 보드만 보면 그만큼을 놓친다. 문구에 **어느 쪽이 한계인지 적는다** — 사용자가
할 일이 다르다. 보드가 한계면 보드를 바꾸고, CPU가 한계면 CPU를 바꾼다.

한쪽만 결측이면 있는 쪽으로 판정한다. 둘 다 결측일 때만 판정 불가다.

### 16.2 ★ 작은 값을 이상치로 거르지 않는다

**작은 값이 맞는 보드가 실재한다.** 최대 4GB는 LGA775 G31/G41·Atom D525 보드에서
맞는 값이고 22건, 2GB는 Atom N550 보드에서 맞고 1건이다. 단순한 하한선으로 거르면
이것들이 함께 사라진다.

대신 **슬롯 수와 맞대 본다.** 모든 실제 DIMM이 1GB 이상이므로 최대 용량이 슬롯 수보다
작을 수는 없다. 이 검사가 걸러 내는 것은 정확히 5건이다 — X570/X399 Taichi와 MEG
X399(전부 `0`), PRIME H570-PLUS와 Pro WS TRX50-SAGE(전부 `1`). **맞는 값은 하나도
걸리지 않는다.**

§8.4의 모순 검사와 같은 종류다. 값 하나만 보면 그럴듯한데 다른 필드와 맞대 보면 틀렸다.

CPU에는 슬롯이 없으니 `0` 이하만 본다 (48건).

### 16.3 오류가 아니라 경고인 이유

제조사의 최대 메모리 사양은 **보수적이고 BIOS 업데이트로 늘어난다.** AM4 보드가
대표적이다. 오류로 단정하면 실제로 쓸 수 있는 조합을 막는다. 규칙 9와 같은
판단이다 (§9.1).

그래서 후보 거르기(ADR-0016)에도 쓰지 않는다. 경고까지만 내는 규칙으로 목록을 빼면
규칙이 "확인이 필요하다"고 말한 것을 화면이 "없다"로 바꾼다.

### 16.4 총량만 본다

**DIMM 하나당 최대 용량은 1차 소스에 없다.** 32GB DIMM까지인 보드에 48GB DIMM을
꽂는 경우는 이 규칙으로 잡히지 않는다. 필드가 생기면 규칙을 나눈다.

## 17. M.2 드라이브를 보드가 받는가 (Phase 1)

| | |
|---|---|
| **등급** | 오류 |
| **입력** | `Storage.form_factor` · `Motherboard.m2_slots` · 보조: `Storage.interface` · `Motherboard.m2_accepts` |
| **판정 가능** | 드라이브 1개 **91.9%** (2026-09-23, §17.5) · 2개 이상 19.9% — 개수는 세지 않는다 (§17.4) |

> **2026-09-22 정정.** 처음에 "M.2 드라이브 수 ≤ 슬롯 수, 99.9% 판정 가능"으로
> 적었다. **틀렸다.** `m2_slots` 배열 길이가 슬롯 수가 아니다 (§17.4).

```
필요 = form_factor가 "M.2"로 시작하는 드라이브 수

pass     필요 = 0                                볼 것이 없다
unknown  드라이브의 form_factor 결측 / m2_slots 결측
unknown  m2_slots가 0인데 보드가 DDR5             (§17.2)
error    m2_slots = 0                            슬롯이 없는데 M.2를 담았다
pass     m2_slots > 0, 드라이브 1개, 그 길이·방식을 받는 행이 있다   (§17.5)
unknown  m2_slots > 0, 그 외                       몇 개인지 알 수 없다 (§17.4)
```

### 17.1 세지 않는 것

`PCIe`(45건, 확장 슬롯에 꽂는 AIC)와 `mSATA`(10건)는 M.2 슬롯을 쓰지 않는다.
세지 않고, **세지 않았다는 사실을 결과에 적는다.**

### 17.2 ★ `0`이 값이다

M.2가 없는 보드는 실재한다 — **DDR2의 100%(48/48), DDR3의 86.3%(542/628)** 가 0이다.
DDR4의 135건도 H110·H310·B150·A320·X99 같은 보급형·서버 칩셋이고 실제로 없다.

**DDR5만 다르다.** 1,066건 중 0은 3건뿐(0.3%)이고 전부 M.2가 있는 보드다
(ASRock B860 Challenger WiFi 2건, ASUS Pro WS 665-ACE). 모집단이 아니라 잡음이라
**DDR5 보드의 0은 판정하지 않는다.**

**빈 목록은 쪼갤 것이 없다** — 그래서 이 `0`만 믿을 수 있다 (§17.4).

### 17.3 E키는 저장장치 자리가 아니다

M.2 E키는 와이파이·블루투스 카드 자리이고 SSD가 들어가지 않는다. 602행,
**601개 보드(20.2%)** 에 섞여 있다. 적재가 E키를 빼고 센다 — 그냥 세면 ASRock
B550M-ITX/ac가 2개로 잡히는데 SSD가 들어가는 것은 1개다.

### 17.4 ★ 배열 길이가 슬롯 수가 아니다 — 그래서 개수를 세지 않는다

**한 슬롯을 크기마다 행으로 쪼갠 레코드가 있다.**

| 보드 | 원본 행 | 실제 슬롯 |
|---|---|---|
| ASUS PRIME B650M-A | `2242-2260`, `2280`, `2242-2260`, `2280` | 2 |
| ASUS PRIME B650M-A WIFI II | `2242/2260/2280` × 2 | 2 |

**같은 하드웨어가 4행과 2행으로 동시에 존재한다.** Gigabyte Z790 AORUS ELITE X도
`2280-22110`·`2280`이 번갈아 8행인데 슬롯은 4개다.

**반대로 덜 적은 레코드도 있다.** Gigabyte Z790 AORUS ELITE AX DDR4는 `22110/2280`
3행인데 슬롯이 4개다. 위아래 어느 쪽으로도 틀리므로 **상한으로도 하한으로도 쓸 수
없다.** 계열을 묶어 보면 **138개 계열이 서로 다른 행 수로 존재한다.**

**크기 표기가 한 가지인 보드만 믿는 것도 안 된다** — ASUS PRIME B650M-A AX6는
`2242/2260/2280` 4행(표기 한 가지)인데 슬롯은 2개다.

그래서 이 규칙은 **있다 / 없다만 본다.** 슬롯이 있으면 몇 개인지 모른다고 말하고,
후보 거르기도 개수로는 하지 않는다 (ADR-0016). `0`인 보드에서 M.2 드라이브를
빼는 것만 한다 — 그 보드에서는 어떤 M.2도 안 들어가므로 좁혀도 잃는 것이 없다.

업스트림이 M.2 목록을 정리하면 개수 검사를 더한다.

근거: `docs/research/storage-slots.md` §4

### 17.5 ★ 드라이브가 하나면 행의 **내용**으로 판정한다 (이슈 #27)

믿을 수 없는 것은 **행의 개수**이지 **행의 내용**이 아니다. 한 슬롯을 크기마다 쪼갠
레코드도, 덜 적은 레코드도, 적힌 행 하나하나는 실제 슬롯의 크기·키·인터페이스를 말한다.
그러니 드라이브가 **하나**면 「이 드라이브를 받는 행이 있는가」로 답할 수 있다 — 몇 개인지는
몰라도 하나가 들어갈 자리는 있다.

```
받는 행 = key가 M
         AND 크기에 드라이브 길이가 있다      2242-2260은 2242·2260, 2280-22110은 2280·22110
         AND 인터페이스가 드라이브 방식을 받는다   PCIe 드라이브 ← "PCIe"·"Gen N"
                                                    SATA 드라이브 ← "SATA"
```

- **적재가 계산해 둔다** — `m2_accepts`: 받는 조합 `길이/방식`의 정렬된 집합
  (`["2242/PCIe", "2280/PCIe", "2280/SATA"]`). 행을 그대로 담지 않는 이유는 같은 제품의
  4행 기록과 2행 기록이 중복 불일치(`disputed`, 이슈 #11)로 잡히기 때문이다. 집합이면 쪼갠
  행과 합친 행이 같은 값이 되고, **내용이 다를 때만** 어긋난다
- **받는 행이 없어도 오류가 아니다.** 덜 적은 레코드가 있다 (§17.4). 판정 불가로 둔다
- **드라이브가 둘 이상이면 판정 불가다.** 두 행이 같은 슬롯을 쪼갠 것일 수 있다
- **속도는 보지 않는다.** PCIe 5.0 드라이브는 4.0 슬롯에 들어가고 느려질 뿐이다.
  x2 슬롯도 같다. 이 규칙은 들어가는지만 본다
- B키만 있는 행(2건)과 키가 없는 행(12건), 폭 25mm 행(`2580-25110`, 91건)은 받지 않는다고 본다
- 판정 가능: 드라이브 1개 조합 기준 **19.9% → 91.9%**. 남은 8.0%는 대부분 SATA 방식 M.2(행
  대부분이 PCIe만 적었다)와 2230·22110 드라이브다

근거: `docs/research/storage-slots.md` §4.4

```
필요 = interface가 "SATA"로 시작하는 드라이브 수   (M.2 SATA는 빼고, §18.1)

unknown  포트 합계가 0이거나 둘 다 결측     (§18.2)
```

### 18.1 `M.2 SATA`와 SAS는 세지 않는다

`M.2 SATA` 드라이브(112건)가 SATA 포트를 가져가는지는 **칩셋의 레인 분배에 달려
있고**, 그 데이터가 없어서 규칙 13이 막혀 있다. 모르는 것을 세지 않는다.
M.2 슬롯은 쓰므로 규칙 17에서는 센다.

SAS(51건)는 일반 보드에 포트가 없다. 세지 않는다.

### 18.2 ★ `0`은 미입력이다 — 규칙 17과 반대다

| 메모리 규격 | SATA 합계 0 | 비율 |
|---|---|---|
| DDR2 | 10 / 48 | 20.8% |
| DDR3 | 72 / 628 | 11.5% |
| DDR4 | 491 / 1,955 | 25.1% |
| DDR5 | 346 / 1,066 | 32.5% |

**세대별 경향이 없다.** SATA가 보편적이던 DDR2·DDR3 보드도 0으로 적혀 있다. 확인한
예 — ASRock B550M-ITX/ac, Asus B660-PLUS TUF GAMING, ASRock B850M Pro RS는 전부
SATA 포트가 있다. **923건(24.9%)이 판정 불가가 된다.**

같은 `0`이라도 M.2는 값이고 SATA는 미입력이다. **필드마다 따로 판단해야 한다.**

## 20. 쿨러가 CPU 소켓을 지원하는가 (Phase 1, 이슈 #17)

| | |
|---|---|
| **등급** | 경고 |
| **입력** | `CPU.socket` · `CPUCooler.cpu_sockets` |
| **충전율** | 100% / 99.9% (2,389/2,392) |

```
pass     쿨러 목록이 CPU 소켓을 덮는다 (§20.2의 표기 보정 포함)
warning  목록에 없다
unknown  CPU 소켓이 없거나 쿨러 목록이 비었다
```

> 메시지 — warning: "쿨러의 지원 소켓 목록에 AM5 소켓이 없습니다. 별도 고정 부품이
> 필요하거나 장착되지 않을 수 있습니다. 제조사 스펙을 확인해 주세요."

### 20.1 오류가 아니라 경고인 이유

CPU 718 × 쿨러 2,389 = 1,715,302조합을 전수로 돌렸다.

| CPU 소켓 | 조합 | 「목록에 없음」 |
|---|---|---|
| AM4 | 205,454 | 12.1% |
| AM5 | 102,727 | 27.1% |
| LGA 1200 | 105,116 | 10.4% |
| LGA 1700 | 140,951 | 28.1% |
| LGA 1851 | 33,446 | 33.1% |

**AM5가 없는 쿨러 647개 중 363개(56%)가 AM4는 적고 있다.** LGA 1851이 없는 790개 중
119개는 LGA 1700을 적었다. 앞 세대 쿨러 상당수가 다음 세대에 그대로 맞는다고
알려져 있다. 그런데 그것은 **데이터로 증명되지 않고** 이 환경에서는 근거 문서를 열
수 없다.

그래서 두 가지를 하지 않는다.

- **그 관계로 묶지 않는다.** 묶으면 커스텀 백플레이트를 쓰는 쿨러에서 거짓 통과가 난다
- **오류로 단정하지 않는다.** 위 363개 중 상당수는 실제로 맞을 것이다

아는 것은 「목록에 없다」뿐이고, 그만큼만 말한다. 규칙 9와 같은 태도다 — 「제조사
스펙을 확인해 주세요」.

경고 규칙이므로 **고르기에서 숨기지 않는다** (ADR-0016). 경고로 목록을 빼면
「확인이 필요하다」가 「없다」로 바뀐다.

### 20.2 표기 보정 — 데이터가 증명한 것만

| 보정 | 근거 | 살리는 조합 |
|---|---|---|
| `TR4` ≡ `sTR4` | §1.1의 등가 표를 그대로 쓴다. 쿨러도 TR4 22 · sTR4 277로 섞어 쓴다 | 220 |
| 쿨러의 `LGA 115` → LGA 1150·1151·1155·1156 | **`LGA 115x`가 잘린 표기다.** 11개 중 10개가 1150·1151을 따로 적지 않았고, DarkFlash Talon은 **제품명에** `LGA 775/ 115x/ 1366`이라고 적혀 있다 | 1,530 (LGA 1151) 외 |

**두 번째는 이 규칙 안에서만 푼다.** `115x`는 **쿨러 고정 구멍 간격이 같다**는 뜻이지
CPU끼리 맞는다는 뜻이 아니다 — LGA 1150 CPU는 LGA 1151 보드에 안 들어간다. §1.1의
등가 표(`sockets.ts`)에 넣으면 규칙 1이 거짓 통과한다. 테스트가 그 누출을 막는다.

`LGA 1200`은 `115x`에 넣지 않는다. 고정 구멍 간격이 같다고 알려져 있지만 **표기가
`115x`를 뜻하지 않는다** — 잘린 문자열을 푸는 것과 호환 관계를 더하는 것은 다른 일이다.

### 20.3 소켓 제조사가 밝힌 장착 호환 — 2026-09-24

§20.1은 앞 세대 호환을 「이 환경에서는 근거 문서를 열 수 없다」며 묶지 않았다. 이제 열 수
있어 **소켓을 만든 회사의 공식 문서**를 읽었다. 두 경우의 근거 강도가 다르다.

| 관계 | 근거 | 처리 |
|---|---|---|
| `LGA 1700` 쿨러 → `LGA 1851` CPU | **Intel 지원 문서**: "existing thermal solutions designed for LGA1700 can fit on LGA1851 without modification" ([000099700](https://www.intel.com/content/www/us/en/support/articles/000099700/processors.html)) | **통과** — 이 규칙은 장착을 본다 |
| `AM4` 쿨러 → `AM5` CPU | AMD가 AM4 쿨러가 AM5에 맞는다고 밝혔다 ([PCGamesN](https://www.pcgamesn.com/amd/ryzen-7000-am5-cooler-compatibility)). 다만 **자체 백플레이트를 쓰는 쿨러는 예외**가 있다 | **경고 그대로** — 이유를 덧붙인다 |

- **LGA 1851은 한 방향만이다.** Intel 문서가 말하는 것은 1700 → 1851이다. 반대 방향은 적지 않는다
- **냉각 성능은 보지 않는다.** Intel도 같은 문서에서 발열·전력 호환은 쿨러 제조사에 확인하라고
  한다. 통과 메시지가 그 사실을 적는다
- **AM4 → AM5를 통과로 올리지 않는다.** 「대부분」은 거짓 통과를 낼 수 있다. 대신 경고 메시지가
  「AMD는 대부분 맞는다고 했지만 자체 백플레이트 쿨러는 예외」라고 말해, 사용자가 무엇을 확인할지 안다
- 규모: LGA 1851이 없는 쿨러 790개 중 119개가 통과로 바뀐다. AM4만 적은 363개는 메시지가 바뀐다
- 이 보정도 **이 규칙 안에서만** 쓴다. `sockets.ts`의 CPU↔보드 등가 표에 넣지 않는다 — LGA 1700 CPU는
  LGA 1851 보드에 안 들어간다

```
pass     그래픽카드를 골랐다, 또는 CPU에 내장그래픽이 있다
warning  그래픽카드를 안 골랐고 CPU에 내장그래픽이 없다
unknown  그래픽카드를 안 골랐고 내장그래픽 값이 비어 있다
```

> 메시지 — warning: "AMD Ryzen 5 7500F에는 내장그래픽이 없어 그래픽카드 없이는 화면이
> 나오지 않습니다. 그래픽카드를 함께 골라 주세요."

**고르지 않은 부품을 보는 첫 규칙이다.** 다른 규칙은 두 부품을 다 골라야 돈다.
그래서 `RULE_PARTS`에는 CPU만 있다 — 그래픽카드는 없어도 되는 것이 아니라 **없는 것이
입력이다.** CPU 하나만 골라도 이 규칙은 돈다.

### 21.1 오류가 아니라 경고인 이유

그래픽카드를 **아직 안 고른 것**과 **빠뜨린 것**을 구별할 수 없다. 오류로 두면 F 모델을
고르는 순간부터 그래픽카드를 고를 때까지 내내 오류가 뜬다. 문구가 「함께 골라 달라」고
말하는 것으로 둘 다를 덮는다.

고르기(ADR-0016)는 좁히지 않는다 — 경고 규칙이고, 좁힐 후보(그래픽카드)도 없다.

### 21.2 「없음」 표기가 둘이다

원본 `specifications.integratedGraphics.model`:

| 값 | 건수 | |
|---|---:|---|
| `"None"` | 418 | 없음 |
| `"0"` | 1 | **없음** — Ryzen 5 7500F 정품. 클럭·셰이더가 전부 0이고 트레이 쌍둥이는 `"None"` |
| 모델 이름 | 371 | 있음 |

판단은 `hasIntegratedGraphics` 하나로 한다. 교차 확인: Intel F·KF 47건 전부 없음,
Ryzen 7000·9000 비F 전부 있음, 7000·9000 F 중 「있음」은 위의 `"0"` 1건뿐이었다.

### 21.3 규칙 7과의 관계

규칙 7은 그래픽카드를 안 골랐으면 **내장그래픽 구성으로 보고** 전력을 합산한다.
내장그래픽이 없는 CPU라면 그 구성은 화면이 안 나온다 — 규칙 7의 합계가 틀린 것은
아니지만, 그 구성 자체가 성립하지 않는다는 것을 규칙 21이 말한다.

## 22. CPU 쿨러가 있는가 — 기본 쿨러 (Phase 1, 이슈 #24)

| | |
|---|---|
| **등급** | 경고 |
| **입력** | `CPU.includes_cooler` · **쿨러를 골랐는가** |
| **충전율** | 100% (CPU 대표 718건. 원본 789건 전부 boolean) |

```
pass     쿨러를 골랐다, 또는 CPU에 기본 쿨러가 들어 있다
warning  쿨러를 안 골랐고 기본 쿨러도 없다
unknown  쿨러를 안 골랐고 기본 쿨러 값이 비어 있다
```

> 메시지 — warning: "AMD Ryzen 7 9800X3D에는 기본 쿨러가 들어 있지 않습니다. CPU 쿨러를
> 함께 골라 주세요."

규칙 21과 같은 구조다 — **안 고른 부품이 입력이고**, `RULE_PARTS`에는 CPU만 있다.
499건(69%)이 기본 쿨러가 없다.

### 22.1 경고인 이유와 말하지 않는 것

- **경고다.** 규칙 21과 같은 이유 — 아직 안 고른 것일 수 있다 (§21.1)
- **기본 쿨러가 그 CPU에 충분한지는 말하지 않는다.** 기본 쿨러의 냉각 성능 데이터가
  없다. 「있다」까지만 말한다 — 근거 없는 수치를 지어내지 않는다

### 22.2 표기를 확인했다

원본 값이 트레이·박스 구분과 맞는다. 같은 칩의 두 레코드에서 박스는 `true`,
`OEM/Tray`는 `false`다 (Ryzen 5 7500F, 5600XT, 5600T). K·KF·X3D 모델은 `false`다
(Core i7 14700K·14700KF, Ryzen 7 9800X3D).

### 21.4 내장그래픽이 있어도 보드에 단자가 있어야 한다

내장그래픽은 **메인보드의 영상 출력 단자**로 나간다. 단자가 없는 보드가 실재한다 —
X570은 후면 단자 목록이 온전한 25건 중 10건에 영상 출력이 없다.

그런데 이것으로 판정하지는 않는다. 보드의 `back_panel_ports`는 자유 형식 문자열이고
**목록이 온전한 것이 21%뿐이다** (1,076건은 이더넷 한 줄만 있다). 목록에 없다고 단자가
없다고 할 수 없다. 그래서 통과 문구가 「화면이 나옵니다」로 단정하지 않고 「보드에 영상
출력 단자가 있어야 한다」고 적는다.

## 23. 노트북용(SO-DIMM) 메모리를 데스크톱 보드에 골랐는가 (Phase 1, 이슈 #25)

| | |
|---|---|
| **등급** | 경고 |
| **입력** | `RAM.form_factor` · `Motherboard.form_factor`(보조) |
| **충전율** | 99.98% (RAM 4,875/4,876) |

```
pass     DIMM 키트 (보드를 볼 필요가 없다)
warning  SO-DIMM 키트 + 일반 데스크톱 보드
unknown  키트 폼팩터 결측 / SO-DIMM인데 보드 폼팩터 결측 / Thin Mini-ITX 보드
```

> 메시지 — warning: "노트북용(SO-DIMM) 메모리가 있습니다: Crucial CT16G56C46S5 …. 데스크톱
> 메인보드는 대부분 DIMM 슬롯이라 들어가지 않습니다. 보드의 메모리 슬롯 형태를 확인해 주세요."

**규칙 2가 보지 않는 것을 본다.** 규칙 2는 DDR 규격만 비교해, SO-DIMM DDR5 키트를 DDR5
데스크톱 보드에 담아도 「메모리 규격이 일치합니다」로 통과시켰다. 「삼성 DDR5 16GB」처럼
검색하면 노트북용 키트가 함께 나와 실제로 고를 수 있다.

### 23.1 표기

RAM 대표 4,582건:

| 원본 값 | 건수 | |
|---|---:|---|
| `288-pin DIMM` · `240-pin DIMM` · `184-pin DIMM` · `UDIMM` | 4,439 | 데스크톱 |
| `262-pin SO-DIMM` · `260-pin SO-DIMM` · `204-pin SO-DIMM` · `200-pin SO-DIMM` | **142 (3.1%)** | 노트북 |

판단은 `isSoDimm` 하나로 한다.

### 23.2 경고인 이유와 판정하지 않는 보드

**보드에 슬롯 형태 필드가 없다.** 「데스크톱 보드 대부분은 DIMM」까지만 말할 수 있어
오류가 아니라 경고이고, 문구가 「확인해 달라」고 말한다.

**Thin Mini-ITX 보드(5건)는 판정하지 않는다** — 규격상 SO-DIMM 슬롯을 쓰기도 한다. 그 보드에
경고를 내면 헛경고다. 판정 불가로 두고 슬롯 형태를 확인하라고 적는다.

보드 폼팩터는 **보조 입력**이다(`optional`). DIMM 키트는 보드 폼팩터가 없어도 판정된다 —
SO-DIMM일 때 Thin Mini-ITX를 가려내는 데만 쓴다.
