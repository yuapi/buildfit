# ADR-0023: Phase 3의 첫 단계로 부품별 3D 렌더링 측정값을 싣는다

## 상태
채택 (2026-09-24)

## 배경

Phase 3(성능 분석)는 벤치마크 시드가 없어 막혀 있었다 (명세 §6.8). **Blender Open Data**는
결과 전체가 CC0이고 CPU·GPU 모두 있다 — 인용 범위 문제가 없다
(`docs/research/blender-open-data.md`).

다만 이것은 **3D 렌더링이라는 용도 하나**의 측정값이다. 명세 §6이 그리는 기능(병목·견적 비교·
업그레이드 진단)은 게임 FPS가 핵심이고, 그 시드는 여전히 없다.

## 결정

**부품 페이지와 부품 비교 페이지에 3D 렌더링 측정값을 싣는다.** 그 이상은 하지 않는다.

- 값: Blender 4.5에서 세 장면(monster·junkshop·classroom) 분당 샘플 수 합의 **중앙값**
- GPU는 **실행이 가장 많은 연산 방식**(NVIDIA OptiX · AMD HIP · Intel oneAPI) — 방식을 함께 적는다
- 실행 **5회 이상**만. 실행 수를 함께 적는다
- 이름을 정규화해 **정확히 같은 것만** 잇는다. **Blender가 기록한 장치 이름을 화면에 그대로 보인다**
- GPU는 **칩 단위**다. 같은 칩의 모든 제품에 같은 값 — 「칩 기준 측정」이라고 적는다
- 비교 페이지는 같은 종류끼리만, ADR-0004의 **체감 언어**로 차이를 말한다
- 측정값이 없으면 **없다고 적는다**

## 이유

- **부품 하나의 사실이라 예측이 필요 없다.** 「이 견적은 몇 점」과 달리 틀릴 수 있는 추론 단계가 없다
- **ADR-0004와 맞는다.** 용도 축 하나로 이름을 붙이고, 측정값 + 출처 링크(§6.6.4의 첫 줄)로 낸다
- **맞추기가 틀리면 가장 나쁘다.** 비슷한 이름으로 잇지 않고, 장치 이름을 보여 사용자가 확인하게 한다

**검토한 대안**

| 대안 | 탈락 이유 |
|---|---|
| 견적 단위 「렌더링 점수」 | CPU 렌더와 GPU 렌더는 같은 눈금이 아니다. 합치면 ADR-0004가 금지한 단일 점수가 된다 |
| 여러 Blender 버전을 합쳐 실행 수를 늘리기 | 버전마다 점수가 다르다. 섞으면 같은 장치도 흔들린다 |
| 가장 높은 방식의 점수 | 실행이 적은 방식의 이상치가 뽑힌다. 사용자가 쓰는 방식은 실행이 많은 쪽이다 |
| 유사 이름 매칭으로 범위를 넓히기 | 틀린 점수가 붙는다. 없는 것보다 나쁘다 |

## 결과

- 테이블 `part_benchmarks`(추가만). 값마다 `source_url`과 스냅숏 날짜를 둔다
- 적재는 **선택 단계**다 — 스냅숏(압축 101MB)을 레포에 넣지 않는다. 배포 절차에 한 줄 더한다
- 게임 FPS 축은 여전히 비어 있다. Phase 3의 나머지는 그 시드가 생긴 뒤에 한다
