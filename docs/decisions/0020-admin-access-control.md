# ADR-0020: 어드민은 공유 비밀 하나로 막고, 비밀이 없으면 배포본에서 아예 없다

## 상태
채택

## 배경

`/admin`은 주소만 알면 누구나 열 수 있고, 거기서 **부품 스펙을 고칠 수 있다.**
`robots.txt`가 `/admin`을 막고 있지만 그것은 색인 거부일 뿐 접근 제어가 아니다.

로컬 전용일 때는 문제가 없었다. **배포하는 순간 문제가 된다.** 스펙 한 값이
바뀌면 판정이 뒤집히고, 사용자는 그 판정을 믿고 부품을 산다 (§5.3).

그런데 ADR-0001이 **회원가입·로그인을 만들지 않는다**고 못 박았다. 개인정보를
다루지 않는 것이 이 프로젝트의 안전 전제다. 어드민 보호는 그 경계에 닿는다.

## 결정

**공유 비밀 하나를 HTTP Basic으로 받는다. 계정은 만들지 않는다.**

| `ADMIN_TOKEN` | 개발 (`next dev`) | 배포본 (`next build`) |
|---|---|---|
| 없음 / 16자 미만 | 그냥 열린다 | **`/admin`이 통째로 404** |
| 16자 이상 | 비밀을 묻는다 (401) | 비밀을 묻는다 (401) |

- **아이디 칸은 보지 않는다.** 계정이 아니라 비밀이라서다. 비워도 되고 아무거나 써도 된다
- **꺼진 상태의 기본값이 「없음」이다.** 환경변수 한 줄을 빠뜨린 배포가 스펙 편집기를
  공개하면 안 된다. 켜는 쪽이 명시적이어야 한다
- **거부는 404로 보인다.** 401 도전은 한 번만 보내고, 그 뒤로는 무엇이 있는지 알려주지 않는다
- 개발 환경만 예외로 열어 둔다. 보강 작업에 설정 단계를 하나 더 얹으면 그만큼 안 채운다

**막는 곳은 둘이다.**

| 어디 | 무엇으로 | 왜 |
|---|---|---|
| `src/proxy.ts` | 경로 규칙 (`/admin/:path*`) | 화면이 그려지기 전에 끊고 **401 도전 헤더**를 보낸다 |
| 각 `page.tsx`, `saveSpecAction` | **데이터를 만지기 전에** | 한쪽을 비껴간 요청이 다른 쪽에 걸린다 |
| `admin/layout.tsx` | 같은 판정 | 새로 생긴 화면이 자기 몫을 빠뜨렸을 때의 그물 |

판정 자체(`lib/admin-gate.ts`)는 프레임워크에 기대지 않는 순수 함수 하나다.
막는 곳마다 규칙이 다르면 한쪽이 빗나간다.

**레이아웃에서만 막으면 늦다.** 프록시를 끄고 확인한 결과, 레이아웃에서 `notFound()`를
던져도 페이지 세그먼트는 이미 렌더되어 **404 응답의 본문에 어드민 데이터가 그대로
실렸다** (필드 이름, 결측 수치, 스펙 키). 각 화면이 데이터를 만지기 전에 스스로 막도록
고쳤고, 같은 응답이 31KB에서 12KB로 줄며 수치가 사라지는 것을 확인했다.
`test/admin-guard.test.ts`가 새 화면이 이걸 빠뜨리는 것을 잡는다.

두 번째 층이 막는 것은 **데이터**다. 화면 이름(`<title>`)은 그래도 남는다 —
그건 첫 번째 층의 몫이고, 두 층이 동시에 빠지는 경우를 위한 설계가 아니다.

## 이유

**검토한 대안**

| 대안 | 탈락 이유 |
|---|---|
| 환경변수 플래그만 (`ADMIN_ENABLED`면 열기) | 보강하려고 켜는 동안은 그냥 공개다. 보강은 며칠씩 걸린다 |
| 배포에서 `/admin` 라우트 제외 | 가장 안전하지만 보강을 로컬에서만 할 수 있다. 결측률 83%를 줄이는 게 지금 가장 큰 개선인데 (`#3`) 그 손을 묶는다 |
| 리버스 프록시 IP 허용 목록 | 인프라에 의존한다. 배포처를 아직 안 정했고, 앱이 스스로를 못 지키는 상태가 남는다 |
| 세션 쿠키 + 로그인 폼 | 폼·세션·만료가 생기고, 그건 ADR-0001이 피하려던 것이다 |

**Basic을 고른 이유**

- 서버에 상태가 없다. 세션도 쿠키도 만료도 없고, 따라서 유출될 사용자별 상태도 없다
- 브라우저가 대신 묻고 대신 기억한다. 화면을 만들 필요가 없다
- 비밀 하나이므로 "누가 고쳤는지"를 기록할 수 없다. **그건 감수한다** — 감사 추적이
  필요해지는 시점은 사람이 둘 이상 보강할 때고, 지금은 아니다. 대신 모든 저장은
  `source_url`과 `verified_at`을 남기므로 **무엇이 왜 그 값인지는 항상 남는다** (§5.3)

**`middleware.ts`가 아니라 `proxy.ts`인 이유**

Next 16에서 `middleware.ts`는 `proxy.ts`로 대체되었고, 이름만 바뀐 게 아니라
**proxy는 Node에서 돈다.** Edge 샌드박스의 `process.env`에는 빌드 때 아는 것만
담기므로, 미들웨어에 두면 배포 환경변수로 넣은 비밀을 못 읽어 **어드민이 영영
404가 된다.** 실제로 그렇게 동작하는 것을 확인하고 옮겼다.

## 결과

**제약**

- **비밀을 잃어버리면 배포본 어드민에 못 들어간다.** 복구 수단이 없다 —
  환경변수를 다시 넣고 재시작하는 것이 유일한 길이다
- 누가 고쳤는지는 남지 않는다 (위 참고). 사람이 둘 이상이 되면 다시 본다
- HTTP에서는 비밀이 평문으로 간다. **배포는 HTTPS여야 한다**
- `next dev`가 열려 있다는 것은 **개발 기계에서 `/admin`이 열려 있다**는 뜻이다.
  공용망에 개발 서버를 노출하지 않는다

**후속 작업**

- 배포 환경변수에 `ADMIN_TOKEN`을 넣는다 (`openssl rand -base64 24`)
- 배포처를 정할 때 `/admin`을 프록시 단에서 한 번 더 막을 수 있으면 막는다. 이 결정은
  그것을 대체하지 않고 그것이 없어도 되게 한다
