# ADR-0022: 국내 유통 판정과 가격을 다루지 않는다

## 상태
채택 (2026-09-23)

대체: ADR-0003 (parts/skus 분리), ADR-0007 (가격 예측 보류).
일부 대체: ADR-0006의 「가격을 다루되 이렇게만 다룬다」와 대안 표의 「가격을 아예 다루지 않기」 탈락 판단.

## 배경

국내 유통 판정(§5.7.1)과 가격(Phase 2·4·5)은 전부 **쇼핑몰 상품 데이터**가 있어야 성립한다.
그 소스를 찾았지만 모두 막혔다 (2026-09-23):

- 네이버 쇼핑 검색 API — 2026-07-31 종료. 남은 검색 API도 저장·캐싱·AI 입력 금지
  (`docs/research/naver-shopping-api-status.md`)
- 11번가 상품검색 — 키 발급이 판매자 회원만 가능. 쿠팡 파트너스 — 시간당 10회.
  다나와 — API 소멸. 카카오 — 쇼핑 검색 미제공 (`docs/research/domestic-availability-sources.md`)
- 가격비교 사이트도 공개 API로 얻지 않는다. **쇼핑몰이 돈을 내고 입점해 EP 피드를 보낸다.**
  같은 데이터를 얻으려면 쇼핑몰과 계약해야 하고, 계약 없는 수집은 데이터베이스제작자 권리·
  부정경쟁방지법 위험이 있다 (`docs/research/price-comparison-data-flow.md`)

쇼핑몰과 계약하는 일은 개발이 아니라 영업이고, 이 프로젝트가 감당할 일이 아니다.

## 결정

**국내 유통 판정과 가격, 그리고 가격이 있어야 성립하는 기능을 전부 폐기한다.**

| 폐기 | 명세 |
|---|---|
| 국내 유통 매칭 파이프라인 | §5.7.1 |
| `skus`·`importers`·`warranty_policies`·`price_history` 테이블, `parts.kr_available`·`kr_checked_at` | §5.8 |
| 가격 연동 + 상품명 정규화 (Phase 2) | §7 |
| 가격 통계 지표 (Phase 4), 계절성 분석 (Phase 5) | §11 |
| 전기요금 포함 총소유비용 비교 | §2.1 |
| 견적 비교의 가격 차액·차액 대비 성능, 차액 사용처 제안 | §6.3, §6.4 |
| 업그레이드 진단의 비용 대비 효과 순위 | §6.5 |
| 국내 총판 사전 | `docs/research/kr-distributor-dictionary.md` |

**남는 것**: 호환성·전력·전기요금·성능 비교(가격 없이). 전기요금은 한전 요율표로 계산하므로
쇼핑몰 데이터가 필요 없다.

**화면은 국내 유통 여부를 말하지 않는다.** OpenDB 전체를 보여준다. 한국에서 못 사는 부품이
목록에 섞이는 것은 받아들인다 — 이 도구가 답하는 질문은 「이 조합이 맞는가」이지 「어디서
파는가」가 아니다.

## 이유

- **소스가 없다.** 공개 API가 사라졌고, 남은 길은 쇼핑몰 계약뿐이다
- **가격 없이도 도구가 완결된다.** ADR-0006이 이미 적었다 — 소켓이 맞는지, GPU가 케이스에
  들어가는지는 가격과 무관하다. Phase 0b·1이 가격 없이 전부 동작하고 있다
- **남겨 두면 비용이 든다.** 명세·스키마·로드맵에 소스 없는 기능이 남아 있으면 매번 「언제
  하나」를 따지게 되고, Phase 0a가 영원히 닫히지 않는다
- **긁어 오지 않는다.** 크롤링은 기술적으로 가능하지만 새 법적 위험을 들인다. 개인정보를
  다루지 않는 것을 안전 전제로 삼는 프로젝트가 그 위험을 받을 이유가 없다

**검토한 대안**

| 대안 | 탈락 이유 |
|---|---|
| 쇼핑몰·수입사와 EP 계약 | 영업이 필요하다. 지금 할 사람이 없다. 나중에 하게 되면 새 ADR로 되살린다 |
| 수동 큐레이션(사람이 「유통 중」 표시) | 유지 부담이 크고 표시가 금방 낡는다. 낡은 「유통 중」은 없는 것보다 나쁘다 |
| 「확인 안 됨」 표시만 남기기 | 모든 부품에 같은 문구가 붙으면 정보가 아니다 |
| 크롤링 | 법적 위험 (위 배경) |

## 결과

- **Phase 0a가 닫힌다.** 남은 항목이 유통 매칭뿐이었다
- 스키마에서 비어 있던 테이블 둘(`skus`·`importers`)과 `parts` 컬럼 둘을 지운다. **모두 0행이다** —
  한 번도 채워진 적이 없어 잃는 데이터가 없다. `part_aliases`는 남긴다 — 가격 정규화(§7)의
  입력이기도 했지만 적재가 OpenDB의 표기 변형을 담는 테이블이고, 표기 변형 수집(§5.2)은 가격과 무관하다
- **localStorage·공유 코드는 바뀌지 않는다.** 가격·유통 필드가 들어간 적이 없다
- 로드맵의 Phase 번호는 **다시 매기지 않는다** — 규칙 번호와 같은 이유다. 폐기한 줄은 폐기로 적는다
- 되살리려면 새 ADR로 한다. 그때는 소스의 약관(저장·캐싱·표시)을 **설계 전에** 읽는다
