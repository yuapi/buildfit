# ADR-0018: 견적서를 붙여넣는다 — 찾아는 주되 고르지는 않는다

## 상태
채택 (2026-09-21)

## 배경

이 도구가 하는 일은 판정이다. 그런데 판정하려면 **부품이 먼저 들어와야** 한다.
지금은 빈 칸 일곱 개를 하나씩 검색해 채워야 한다.

그런데 국내 사용자는 대개 **이미 견적서를 들고 온다.** 조립 PC를 사려는 사람은
쇼핑몰이나 조립 업체에서 부품 목록을 받아 보고, 그걸 들고 "이 조합 괜찮나"를
묻는다. 그게 이 도구가 답하려는 바로 그 질문이다.

```
CPU: AMD 라이젠7-5세대 9800X3D (그래니트릿지) (멀티팩)
메인보드: ASUS PRIME B650M-A II 대원씨티에스
그래픽카드: GIGABYTE RTX 4070 Ti SUPER 에어로 OC 16G
...
```

이 글을 붙여넣으면 끝나야 하는데, 지금은 일곱 번 검색해야 한다.

### 왜 지금 할 수 있게 됐나

ADR-0017 이전에는 불가능했다. 「라이젠」도 「지포스」도 0건이었고, 띄어쓰기
한 칸에 결과가 갈렸다. 한글 사전과 구분자 평탄화가 생기면서 **견적서 줄을
카탈로그 이름과 맞댈 수 있게 됐다.**

## 결정

**붙여넣은 글을 줄 단위로 찾아 보여주되, 아무것도 자동으로 채우지 않는다.**

### 1. ★ 찾아는 주되 고르지는 않는다

| 찾은 것 | 화면 | 실측 비율 |
|---|---|---:|
| 정확히 하나 | 미리 골라둔다 | 69.8% |
| 여럿 | **고르게 한다.** 우리가 고르지 않는다 | 30.2% (평균 2.7개) |
| 없음 | 못 찾았다고 말하고 무엇으로 찾았는지 적는다 | 0.0% |

근거는 `docs/research/quote-line-matching.md`. 표본 420건이다.

**가장 중요한 수치는 단일 오답 0건이다.** 여럿이면 고르게 하면 되고 못 찾으면
못 찾았다고 하면 되지만, **하나를 잘못 확정하면 사용자는 확인 없이 틀린 부품을
견적에 넣는다.** 그 위에서 돌아간 호환성 판정은 아무 의미가 없다.

이것은 ADR-0009가 세운 선과 같은 것이다 — **거짓 통과가 최악의 결과다.**
거기서는 데이터가 없으면 `unknown`이었고, 여기서는 확실하지 않으면 고르게 한다.

그리고 **버튼을 누르기 전까지 견적은 바뀌지 않는다.** 화면에서 본 것만 들어간다.

### 2. 형식을 가정하지 않는다

쇼핑몰마다 견적서 모양이 다르고, **이 환경에서 실제 견적서를 확인할 방법이 없다**
(국내 쇼핑몰 도메인이 전부 차단돼 있다). 그래서 파서를 쓰지 않는다.
줄을 나누고, 줄마다 부품처럼 생긴 것을 찾을 뿐이다.

부품 줄이 아니면 후보가 0개로 나오고 화면이 그렇게 말한다. **형식이 틀려서
실패하는 경로가 없다.**

### 3. ★ 줄 앞 이름표는 찾는 말이 아니라 어디서 찾을지다

`CPU: AMD 라이젠7 9800X3D`에서 `CPU`를 검색 조각으로 쓰면 **이름에 `cpu`가 든
부품**만 찾게 되어 줄이 통째로 빗나간다. 실제로 0건이 났다.

이름표를 카테고리로 쓰면 줄이 살아날 뿐 아니라 범위도 좁아진다.
**구분자가 있어야 이름표로 본다** — 없으면 `Corsair …`의 첫 낱말도 이름표가 된다.

### 4. ★ 다루지 않는 부품은 "못 찾음"과 구분해 말한다

이름표 사전에 **취급하지 않는 카테고리도** 적어둔다 — SSD·모니터·키보드·운영체제.

"못 찾았다"는 사용자를 다시 쳐보게 만들지만 "아직 다루지 않는다"는 그렇지 않다.
그리고 그런 줄은 **아예 찾지 않는다.** 「SSD: 삼성 990 PRO」로 삼성 메모리를
부를 이유가 없다.

### 5. ★ 검색창과 정책이 반대다

| | 검색창 (ADR-0017) | 견적서 |
|---|---|---|
| 모르는 한글 | **0건을 낸다.** 무시하면 검색이 조용히 넓어진다 | **버린다.** 잡음이 섞여 있는 것이 정상이다 |
| 타이핑 중 표기 | 받는다 (「라이」 → ryzen) | **안 받는다.** 다 쓴 글이다 |
| 안전장치 | 결과가 곧 답이다 | 고르게 한다. 확인 없이 들어가지 않는다 |

두 번째가 특히 중요하다. 검색창의 앞부분 일치를 그대로 쓰면 **「개」가
「갤럭시」로 잡힌다** (받침만 다르다). "수량 1개"가 GALAX 그래픽카드를 불렀다.

### 6. 글자가 없는 줄은 부품 줄이 아니다

「합계 2,480,000원」은 숫자만 남아 `480`·`000`이 되는데, 그걸로 찾으면 엉뚱한
부품이 줄줄이 나온다. **부품 이름에는 반드시 글자가 있다.**

### 7. 한 칸에 하나. 겹치면 넣지 않고 말한다

두 줄이 같은 칸을 가리키면 뒤엣것을 넣지 않고 그렇다고 적는다.
조용히 덮으면 사용자는 자기가 고른 것이 사라진 줄 모른다.

## 이유

### 검토한 대안

| 대안 | 탈락 이유 |
|---|---|
| 쇼핑몰별 견적서 파서 | 형식을 확인할 방법이 없다(차단). 형식이 바뀌면 조용히 깨진다 |
| 가장 잘 맞는 하나를 자동으로 채운다 | 단일 오답이 0이라는 것은 **확정한 것에 한해서**다. 여럿 중에서 점수로 하나를 고르면 그 보장이 사라진다 |
| 줄마다 검색창을 열어 사용자가 찾게 한다 | 지금과 같다. 일곱 번 찾는 수고가 그대로다 |
| 부품 줄이 아닌 줄을 지우라고 안내한다 | 사용자가 견적서를 손질하게 만든다. 우리가 걸러야 한다 |
| LLM으로 줄을 해석한다 | 없는 부품을 지어낼 수 있다. 「근거 없는 수치를 지어내지 않는다」와 정면으로 부딪힌다 |

### 왜 점수를 매기지 않는가

"가장 비슷한 것"을 뽑으려면 점수가 필요하고, 점수에는 임의의 문턱이 따라온다.
문턱을 넘긴 것을 자동으로 넣는 순간 **확인 없이 틀린 부품이 견적에 들어가는
경로**가 생긴다.

지금 방식에는 그 경로가 없다. 조각은 전부 만족(AND)이고, 만족하는 것이 하나면
확정, 여럿이면 고르기다. **"비슷함"을 판단하는 자리가 아예 없다.**

## 결과

- **단일 오답이 0이 아니게 되면 멈춘다.** 그게 이 기능의 전제다.
  `npm run measure:quote --workspace @buildfit/ingest`로 다시 잰다
- 사전(`KO_ALIASES`)에 말을 더하면 다시 잰다. 확정률이 바뀐다
- 취급 카테고리를 늘리면 `QUOTE_LABELS`의 `category: null` 항목을 옮긴다.
  스토리지가 들어오면(이슈 #5) 그 한 줄이다
- **실제 견적서를 구하면 실측의 변형 목록을 다시 짠다.** 지금 것은 우리가
  아는 변형뿐이라 수치를 하한 근처로 읽어야 한다
- 줄마다 쿼리 하나다. 11줄에 31ms — 상한은 40줄이다. 카탈로그가 커지면 다시 본다
