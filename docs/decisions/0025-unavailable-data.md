# ADR-0025: 자동으로 확보할 수 없는 데이터는 사용 불가로 본다

## 상태
채택 (2026-09-25). 사용자 지시:

> 수동 데이터 추가를 제외하고, 자동 확보가 불가능한 경우 우선 해당 데이터를 사용불가로 판단하고 진행

## 배경

판정 불가가 큰 규칙(6·9·12·24)과 보류한 규칙(10·11·13·14), 막힌 Phase 3 기능이
전부 **사람이 데이터를 넣어야 풀리는** 이슈로 남아 있었다 (#3 케이스 데이터 보강, #4 원본에
필드 없음, 게임 FPS 시드). 사람이 채울 계획이 없는데 「보류」로 두면, 다음 세션마다 같은 막힌
길을 다시 들여다본다.

## 결정

**데이터마다 자동 경로가 있는지 본다. 없으면 사용 불가로 보고, 그 데이터에 기대는 기능은
보류가 아니라 폐기한다.** 수동 입력(어드민 보강 캠페인)은 계획하지 않는다.

| 데이터 | 자동 경로 | 판단 |
|---|---|---|
| 케이스 PSU 폼팩터·쿨러 높이·PSU 길이 (규칙 6·9·24) | **있다** — 업스트림 OpenDB가 6시간마다 자동 동기하며 채운다. 우리 clone(2026-09-21) 이후 4일 동안 +98·+30·+108건 | **쓴다.** 원본을 다시 받아 재적재한다. 채워지지 않은 것은 지금처럼 판정 불가 |
| 메인보드 출시 연도 (규칙 12) | 같은 4일 동안 채워진 것이 0건 | 원본에 있는 만큼만. 나머지는 사용 불가 — 판정 불가와 소켓 하한(§12.5) 그대로 |
| 라디에이터 장착 위치 (규칙 10) | 원본 스키마에 필드 없음 | **사용 불가 → 규칙 폐기** |
| 메모리 높이 (규칙 11) | 원본 스키마에 필드 없음 | **사용 불가 → 규칙 폐기** |
| 칩셋별 M.2–SATA 공유 (규칙 13) | 원본 스키마에 필드 없음 | **사용 불가 → 규칙 폐기** |
| 보드 PCIe 레인 분배 (규칙 14) | 원본 스키마에 필드 없음 | **사용 불가 → 규칙 폐기** |
| 게임 FPS | **없다** (아래) | **사용 불가 → 명세 §6.2~§6.7 폐기.** Phase 3는 부품별 3D 렌더링 측정값(ADR-0023)까지다 |

**게임 FPS에서 찾은 유일한 공개 후보를 쓰지 않는 이유.** OpenML `fps_benchmark`(did 44992, 원본 42737)는
CC BY로 표기되어 있지만, 설명에 **2020년 6월 userbenchmark.com·fpsbenchmark.com·techpowerup.com에서
모았다**고 적혀 있다. 원 사이트가 재사용을 허락한 것이 아니라 올린 사람이 붙인 라이선스다 —
ADR-0022가 피한 긁어 오기 위험을 그대로 들인다. 게다가 GPU 446종·CPU 358종 중 RTX 30 이후와
Ryzen 5000 이후가 없다 (Quadro RTX 4000이 가장 새것이다).

## 이유

- **막힌 길을 「보류」로 두면 비용이 계속 든다.** 세션마다 같은 이슈를 열어 보고 같은 결론에 닿는다
- **자동 경로가 있는 것은 버리지 않는다.** 케이스 데이터는 업스트림이 채우고 있다. 사람을 들이지
  않고 늘어나는 유일한 길이므로 재동기를 명령 하나로 만든다
- **판정은 바뀌지 않는다.** 결측은 여전히 판정 불가이고, 근거 없는 수치를 지어내지 않는 원칙
  (CLAUDE.md)도 그대로다. 바뀌는 것은 「언젠가 채운다」는 계획뿐이다

## 결과

- 이슈 #3(케이스 데이터 수동 보강)·#4(규칙 10·11·13·14 보류)를 닫는다 (not planned)
- 명세 §4.2에서 규칙 10·11·13·14를 **폐기**로 적는다. **번호는 다시 쓰지 않는다** — 21~24를 새로 쓴 것처럼,
  건너뛴 자리를 메우지 않는다
- 명세 §6.2~§6.7과 §11의 Phase 3를 「렌더링 측정값까지」로 줄인다. 되살리려면 이용 허락이 분명한
  게임 성능 출처를 찾아 새 ADR로 한다 (ADR-0022의 가격과 같은 조건)
- `/admin`과 사용자 신고는 **그대로 둔다.** 들어오는 값을 받는 통로이지, 계획된 입력 작업이 아니다
- 원본 재동기 명령을 둔다 (별도 이슈)
