# ADR-0001: 회원가입을 만들지 않는다

## 상태
채택

## 배경

견적 도구는 "저장"과 "다시 보기"가 필요하고, 보통 이 요구는 회원가입으로 해결한다.
하지만 이 프로젝트에는 두 가지 사정이 있다.

1. 개인 프로젝트이고 초기 유입이 전부다. 로그인 장벽은 유입을 크게 깎는다.
   (`pc-builder-spec.md` §3)
2. 이 서비스는 `pipeline-plan.md`의 자가수복 파이프라인을 실험하는 대상이기도 하다.
   자가수복 루프가 로직을 잘못 고쳐도 사용자 피해가 없어야 실험이 성립한다.
   (`pc-builder-spec.md` §10.6)

개인정보를 다루는 순간 2번의 안전 전제가 깨진다. 자가수복이 인증·인가 경로를 건드리면
그건 더 이상 "고장나도 괜찮은 서비스"가 아니다.

## 결정

**회원가입과 로그인을 만들지 않는다.** 지속성은 다음 두 가지로 확보한다.

- 견적의 정본(진실 소스)은 **공유 URL**. 견적 내용을 URL에 인코딩한다
- 편의 기능으로 **브라우저 localStorage**에 저장 목록·최근 기록·입력값 보관
  (`pc-builder-spec.md` §8A)

## 이유

- **유입 > 지속성.** 처음 조립하는 사람이 검증 한 번 하려고 가입하지 않는다.
  타겟(§1.3) 세 부류 모두 일회성 방문 비중이 높다
- **개인정보 없음 = 사고 비용 없음.** 금전 거래 없음, 개인정보 없음, 로그인 없음이면
  최악의 장애도 "서비스가 잠깐 안 됨"에서 끝난다. 이것이 §12.1 자가수복 범위 개방을
  진행할 수 있는 근거다
- **URL 인코딩이면 서버 상태가 필요 없다.** 공유 링크가 곧 데이터이므로, 견적 공유에
  DB도 세션도 필요하지 않다

**검토한 대안**

| 대안 | 탈락 이유 |
|---|---|
| 소셜 로그인만 제공 | 장벽은 낮아지지만 개인정보(이메일·식별자)는 여전히 들어온다 |
| 익명 계정(서버 발급 토큰) | 서버에 사용자별 상태가 생기고, 그 순간 자가수복의 blast radius가 커진다 |
| 저장 기능 자체를 빼기 | §8A.1의 `prefs`(가구 월 사용량 등)를 매번 재입력하게 만들면 전기요금 기능을 아무도 안 쓴다 |

## 결과

**제약**

- 서버 측 사용자 식별자가 없으므로 "내 견적 목록"은 브라우저 단위다. 기기 간 동기화는
  불가능하고, 이 점을 UI에 명시해야 한다 (§8A.3)
- 시크릿 모드·스토리지 차단·용량 초과 시 저장이 실패한다. **저장 실패를 정상 경로로
  처리**해야 한다 (§8A.4)
- FPS 제보(§6.6.5)와 오류 신고(§5.5)의 중복 방지는 브라우저 단위 토큰으로만 가능하다.
  완전한 방지는 포기하고 이상치 필터링으로 보완한다
- localStorage가 유일한 지속성 수단이므로 저장 포맷의 하위 호환이 중요해진다 → ADR-0005

**후속 작업**

- 견적 → URL 인코딩 스킴 결정 (해시 길이, 버저닝)
- localStorage 스키마 v1 정의 및 마이그레이션 함수 자리 마련
- "브라우저 데이터를 지우면 사라집니다 / 백업은 URL 복사" 안내 문구
- 견적 목록 JSON 내보내기·가져오기 (Phase 1)
