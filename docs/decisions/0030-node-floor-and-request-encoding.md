# ADR-0030: Node 하한은 보안 릴리스를 따르고, 압축된 요청 본문은 받지 않는다

## 상태
채택 (2026-10-26, 이슈 #150)

## 배경

2026-10-21 Node.js 보안 릴리스(22.x는 **22.23.4**)가 나왔다. 서버는 22.23.3이다. 22.x에 해당하는 것:

| CVE | 등급 | 내용 |
|---|---|---|
| CVE-2026-111497 | High | Brotli 해제기의 경계 밖 쓰기. 공격자가 준 Brotli 데이터를 `node:zlib`로 풀면 코드 실행 가능 |
| CVE-2026-106069 | High | 앞자리 0이 붙은 IPv4로 TLS 호스트 이름 검사 우회 |
| CVE-2026-105482 | High | `dns.resolve`가 NUL에서 이름을 자름 |
| CVE-2026-105481 외 | Medium | keep-alive 응답 스머글링, DNS SAN의 비정규 IPv4, 스냅숏의 `randomUUID` 캐시 |

`package.json`의 `engines.node`는 `>=20.9`였다. Node 20은 지원이 끝났다. CI는 `node-version: 22`라
러너 이미지에 캐시된 22.x로 돌았다.

### 이 앱에서 Brotli 해제에 닿는가 — 2026-10-26 확인

**닿지 않는다.** 확인한 것:

- **Next 16.4.2는 요청 본문의 `Content-Encoding`을 풀지 않는다.** 설치된 `next/dist`에서 압축 해제를
  부르는 곳은 이미지 최적화(`server/image-optimizer.js`의 `decodeResponseBody`)뿐이고, 그것은 **바깥에서 받아 온
  응답**을 푼다. `images.unoptimized`라 `/_next/image`는 404다 (`next-server.js`가 최적화 전에 404를 낸다)
- 서버 동작은 본문을 그대로 읽는다. 라우트 핸들러는 `/healthz`(GET) 하나다
- 앱·DB 계층·적재에 `zlib`이 없다. 벤치마크 적재는 `unzip` 명령, OpenDB는 git이다. 앱은 실행 중에 바깥으로
  `fetch`하지 않는다 (undici는 응답을 푼다 — 그래서 바깥 호출을 붙이면 이 판단을 다시 한다)
- Caddy의 `encode zstd gzip`은 응답만 압축한다. 요청 본문을 풀지 않는다

Next 16.4.3(2026-10-23)은 버그 수정 백포트다. 10-14 보안 권고 3건(GHSA-p3m5·673q·2464)의 수정판이 16.4.2다.

## 결정

### 1. Node 하한 = 그 줄기의 최신 보안 릴리스
- `engines.node`를 `>=22.23.4`로. **하한은 이 한 곳에만 적는다** — `scripts/node-floor.mjs`가 읽는다
- 첫 설치(`setup-server.sh`)는 하한 아래면 멈춘다
- 배포(`deploy.sh`)는 **알리기만 한다.** 배포를 막아도 옛 릴리스가 같은 Node에서 계속 돌 뿐이라 얻는 것이 없다.
  Node는 sudo가 필요해 사람이 올린다 (`apt`)
- CI는 `check-latest: true`로 최신 22.x를 받는다
- 다음 보안 릴리스가 나오면 하한을 그 버전으로 올린다. `apps/web/test/node-floor.test.ts`가 22.23.4 아래로 내려가는 것을 막는다

### 2. 압축된 요청 본문은 415
`proxy.ts`가 `Content-Encoding`이 있고 `identity`가 아니면 **어떤 처리보다 먼저** 415로 돌려보낸다.

지금은 닿지 않지만 막는다. 브라우저는 요청 본문을 압축해 보내지 않으므로 잃는 것이 없고, 프레임워크·프록시가
바뀌어 요청 본문을 풀기 시작해도 공격자가 고른 압축 데이터가 해제기에 들어가지 않는다. 압축 해제기의 메모리
안전 버그는 되풀이되는 종류다.

### 3. CI 토큰은 읽기만
`ci.yml`에 `permissions: contents: read`. 검사는 코드를 읽기만 한다. 기본 권한을 레포 설정에 맡기지 않는다.

## 이유

| 대안 | 탈락 이유 |
|---|---|
| `.npmrc`에 `engine-strict=true` | 서버 Node가 낮으면 `npm ci`가 실패해 배포가 멈춘다. 옛 릴리스가 같은 Node로 계속 돌 뿐이고, 급한 수정도 못 나간다 |
| CI에 하한 검사 단계 | `check-latest`로 이미 최신이다. `verify-local.sh`(ADR-0029)가 같은 단계를 돌아 개발 서버 Node가 낮으면 로컬 검증 경로가 막힌다 |
| CI 버전을 정확히 고정 (`22.23.4`) | 다음 보안 릴리스 때 또 고쳐야 한다. 하한은 `engines`가 맡는다 |
| 415 대신 Caddy에서 거부 | Caddy 설정은 레포 밖(`/etc/caddy`)이라 테스트로 지킬 수 없다. 앱을 다른 프록시 뒤에 두어도 그대로 막힌다 |
| 압축을 풀어 받기 | 쓰는 클라이언트가 없다. 해제 크기 제한 같은 일만 는다 |

## 결과
- Node를 올리기 전까지 배포 기록에 「주의: 서비스 Node를 올려야 해요」가 남는다
- 압축된 본문으로 서버 동작을 부르는 클라이언트는 415를 받는다. 브라우저는 해당 없다
- 바깥 서비스를 `fetch`로 부르게 되면 응답 해제(undici)가 다시 공격면이 된다. 그때 이 ADR을 다시 본다
