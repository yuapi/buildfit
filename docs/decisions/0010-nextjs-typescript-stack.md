# ADR-0010: Next.js + TypeScript 단일 스택을 쓴다

## 상태
채택

## 배경

이슈 #1(OpenDB 조사)이 끝나 데이터 쪽 불확실성이 해소되면서, 스택을 정할 수 있게
됐다. `pc-builder-spec.md` §9는 이 결정을 `[환경의존: 선호에 따라 조정]`으로 열어두고
"백엔드: 무엇이든. **기존에 익숙한 것 우선**"이라고만 적어두었다.

그 사이에 확정된 제약들이 선택지를 좁혔다. 정리는
`docs/research/stack-requirements.md`에 있고, 요점은 셋이다.

1. **SSR 또는 정적 생성이 요구사항이다** (§8). 검색 유입이 성장 경로이고,
   `/part/:slug` 롱테일이 적재 대상 20,282건만큼 생긴다
2. **호환성 규칙 엔진이 두 곳에서 필요하다.** 견적 편집 중 즉시 판정(클라이언트)과
   `/build/:hash` 공유 링크의 SSR 결과(서버)
3. **부하가 없다.** 사용자 약 100명, 피크에도 초당 1건 미만. 성능은 선택 기준이 아니다

## 결정

**Next.js(App Router) + TypeScript 단일 스택.**

| 구분 | 확정 |
|---|---|
| 프론트·백엔드 | Next.js (TypeScript), SSR/ISR |
| DB | PostgreSQL — `part_specs` key-value를 JSONB로 |
| 규칙 엔진 | **프레임워크 비의존 순수 TS 모듈.** 클라이언트·서버 공유 |
| 어드민 | 같은 앱 안의 라우트 |
| 정규화 워커 (Phase 2) | Python 별도 서비스. DB로만 연결 |
| 캐시·큐 | **두지 않는다** |

## 이유

- **규칙 엔진을 한 벌만 유지한다. 이것이 결정적인 이유다.**
  호환성 판정이 이 프로젝트의 핵심 자산인데(§2.2), 구현이 두 벌로 갈리면
  "편집 중엔 통과였는데 공유 링크에선 오류"가 난다. 규칙이 Phase 0의 8개에서
  Phase 1의 14개로 늘어나는 계획이라 어긋날 여지가 계속 커진다.
  `pipeline-plan.md` §9.3이 회귀 테스트를 판정자로 세운 구조에서 **판정 로직이
  두 벌인 것은 그 자체로 사각지대**다
- **SSR 요구가 스택 선택을 사실상 지배한다.** ISR로 롱테일 2만 페이지를 빌드 없이
  처리할 수 있다
- **견적 편집은 상태가 많은 UI다.** 부품 6종을 바꿔가며 즉시 판정을 보고,
  §8A의 localStorage 연동과 URL 인코딩이 붙는다. 클라이언트 로직 비중이 작지 않다
- **Phase 2 Python 워커와의 결합이 약하다.** 임베딩 정규화는 DB로만 연결되는
  배치이므로(§7.2) 언어가 달라도 경계가 깨끗하다
- 회원가입이 없어(ADR-0001) 인증·세션 스택이 통째로 빠진다. 프레임워크 선택에서
  가장 성가신 부분 하나가 사라진다

**검토한 대안**

| 대안 | 탈락 이유 |
|---|---|
| Python 단일 (Django + HTMX) | Django admin이 §5.3 어드민을 거의 공짜로 덮는 것은 실질 이점이다. 하지만 **규칙 엔진이 서버 전용이 되어** 부품을 고를 때마다 서버 왕복이 생긴다. 조사에서 어드민 보강 대상이 수십 건 규모로 확인돼(§6.2) admin이 절약하는 시간의 가치가 예상보다 작아진 것도 영향을 줬다 |
| SvelteKit | 같은 이점에 더 가볍지만 생태계와 레퍼런스가 얕다. 부하가 없어 성능 이점은 의미가 없다 |
| 분리 (Go·Rust 백엔드 + TS 프론트) | 배포 단위가 둘로 늘고 규칙 엔진도 두 벌이 된다. 부하 없는 프로젝트에서 얻는 것이 없다 |

## 결과

**제약**

- **규칙 엔진은 Next.js에 의존해서는 안 된다.** DB 접근도, 프레임워크 API도 쓰지 않는
  순수 함수 모듈로 분리한다. 입력은 부품 객체, 출력은 `pass | fail | unknown`(ADR-0009).
  이래야 스택을 바꿔도 이식되고, `pipeline-plan.md` §9.1 회귀 스위트의 중심이 된다
- ~~**Phase 2부터 2언어가 된다.** 정규화 워커가 Python이다.~~ — Phase 2(가격 연동·정규화)를
  폐기해 워커도 만들지 않는다 (ADR-0022). 스택은 TypeScript 하나다
- **ISR 재검증 주기를 §5.6 갱신 주기(OpenDB sync)와 맞춰야 한다.** 부품 페이지는 주 1회
  OpenDB sync다. (가격 일 1회는 가격과 함께 폐기 — ADR-0022)
- **Node 런타임이 배포 대상에 추가된다.** `pipeline-plan.md`의 컨테이너 이미지와
  의존성 업데이트(Renovate) 범위에 들어간다. Next.js 메이저 업그레이드는 §3.1에 따라
  **T2(승인 필수)** 로 분류된다
- localStorage 접근은 SSR에서 실행되면 안 된다. 클라이언트 경계를 명시적으로 긋는다
  (§8A.4의 저장 실패 처리와 함께 다룬다)
