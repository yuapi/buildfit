# ADR-0012: 공유 URL 포맷은 add-only이며 구버전 디코더를 영구 보존한다

## 상태
채택

## 배경

`pc-builder-spec.md` §8A.3이 정한 구조다.

> localStorage는 편의 기능이고, **견적의 정본은 공유 URL이다.**
> 이 구조 덕분에 localStorage가 완전히 날아가도 사용자는 URL만 있으면 복원할 수 있다.

회원가입이 없으므로(ADR-0001) 서버에 견적을 저장하지 않는다. 견적의 내용 전체가
URL 안에 들어간다.

**그래서 URL은 localStorage보다 더 강한 제약을 받는다.** ADR-0005가 다룬 롤백
비대칭이 여기서는 더 나쁘다.

| | localStorage | 공유 URL |
|---|---|---|
| 어디에 있나 | 그 사용자의 브라우저 | 커뮤니티 게시물, 메신저, 북마크, 검색 색인 |
| 우리가 고칠 수 있나 | 읽기 코드로 마이그레이션 가능 | **불가능. 이미 뿌려졌다** |
| 깨지면 | 저장 목록 일부 손실 | **"이거 봐라"고 던진 링크가 죽는다** |

견적 공유는 §6.7이 노린 유입 경로이기도 하다. 죽은 링크는 유입도 신뢰도 같이 깎는다.

## 결정

**공유 URL 포맷을 버전 있는 바이너리 코드로 두고, 한 번 배포한 버전의 디코더는
영구 보존한다.**

```
v1 레이아웃 (base64url, 패딩 없음)

  [0]      포맷 버전 (1)
  [1]      슬롯 존재 비트마스크 (cpu·mb·gpu·case·psu·ram)
  [2..]    존재하는 슬롯마다 UUID 16바이트 (고정 순서)
           ram은 개수 1바이트 + (개수 × 16바이트)
```

**규칙**

1. **v1의 의미를 바꾸지 않는다.** 바이트 배치, 슬롯 순서, 비트 위치 전부 고정
2. 부품 종류를 늘리려면 **v2를 새로 만든다.** v1 디코더는 그대로 둔다
3. **모르는 버전은 조용히 실패한다.** 앱이 죽지 않고 "이 링크를 읽을 수 없습니다"로
   처리한다 (ADR-0005 규칙 4와 같은 태도)
4. 디코드 실패·부품 없음은 **판정 불가와 구분한다.** 링크가 깨진 것과 데이터가 없는
   것은 사용자가 할 행동이 다르다
5. **포맷 변경은 T2(승인 필수)** 다. `autonomous-pipeline-plan.md` §10.5가 저장 포맷을
   T2로 둔 것과 같은 이유이며, URL은 더 되돌릴 수 없다

## 이유

- **UUID를 그대로 쓰면 URL이 길어진다.** 문자열 6개를 JSON으로 담으면 300자가 넘는다.
  원시 바이트로 담고 base64url하면 전체 구성이 **약 130자**다
- **서버 상태가 필요 없다.** 해시를 DB에 저장하는 방식이면 그 DB가 링크의 수명을
  결정한다. 자체 완결적 코드는 DB가 비어도 복원된다
- **비트마스크가 부분 구성을 공짜로 처리한다.** 부품을 다 고르지 않은 견적도 공유된다
- 슬롯 순서를 고정하면 **같은 구성은 항상 같은 코드**가 된다. 캐시와 §6.7의
  `/vs/:hashA/:hashB` 비교에 유리하다

**검토한 대안**

| 대안 | 탈락 이유 |
|---|---|
| 서버에 해시→견적 저장 | 링크 수명이 DB에 묶인다. 회원가입 없는 구조에서 정리 정책도 애매하다 |
| JSON을 base64로 | 300자 이상. 키 이름이 매번 실린다 |
| slug 나열 (`/build/amd-ryzen-7-9800x3d+...`) | 읽기 좋지만 500자가 넘고, slug가 바뀌면 링크가 죽는다 |
| 짧은 순번 id 도입 | 부품마다 정수 id를 따로 관리해야 하고, 재적재 시 안정성을 보장하기 어렵다 |

## 결과

**제약**

- **부품 UUID가 안정적이어야 한다.** 적재 스크립트가 `opendb_id` 기준 upsert라
  재적재해도 `parts.id`가 유지된다. **이 성질을 깨면 기존 공유 링크가 전부 죽는다.**
  적재 로직 변경 시 최우선 확인 항목이다

- **★ `parts_opendb_id_uq` 유니크 인덱스를 제거하지 않는다.** 이것이 id가 조용히
  바뀌는 것을 막는 실제 방어선이다. 충돌 키가 잘못돼 있어도 이 인덱스가 있으면
  중복 행이 만들어지지 않고 적재가 실패한다 — 눈에 보이는 고장으로 바뀐다.
  인덱스를 지우면 같은 상황이 **조용한 id 변경**이 되고, 그때는 링크가 죽는 걸
  아무도 모른다

  > **경위와 정정.** 처음 구현은 `slug`를 충돌 키로 썼다. slug는 제품명에서 파생되므로
  > 업스트림이 이름을 고치면 바뀐다. 부품 상세 페이지를 만들며 발견해 `opendb_id`
  > 기준으로 바로잡았다.
  >
  > 처음에는 이 버그의 결과를 "`parts.id`가 바뀌어 링크가 죽는다"로 적었는데,
  > **실제로 재현해보니 그렇지 않았다.** 제품명 변경을 모사하고 옛 코드로 돌리면
  > `parts_opendb_id_uq` 위반으로 **적재가 중단된다**. 데이터가 낡을 뿐 id는 바뀌지
  > 않는다. 고쳐야 할 버그인 것은 같지만 심각도가 다르므로 기록을 바로잡는다.
  >
  > 이 재현에서 얻은 것이 위의 인덱스 항목이다. 방어선이 충돌 키가 아니라
  > 유니크 인덱스였다.
- OpenDB에서 부품이 사라져도 **`parts` 행을 지우면 안 된다.** §5.6이 단종 부품을
  지우지 않기로 한 이유에 "공유 링크 보존"이 추가된다
- v1 디코더는 리팩터링 대상이 아니다. 테스트로 고정한다
- 코드가 130자라 사람이 읽을 수 없다. 공유 화면에 **무엇이 담긴 링크인지** 텍스트로
  함께 보여준다

## v2 (2026-09-19) — CPU 쿨러 슬롯 추가

Phase 1의 규칙 9를 넣으며 견적에 CPU 쿨러가 생겼다. 이 ADR이 정한 대로
**v1을 고치지 않고 v2를 새로 만들었다.**

- 앞의 다섯 슬롯(`cpu, motherboard, gpu, pcCase, psu`) 순서를 그대로 물려받는다.
  쿨러는 비트 5, 메모리는 비트 6으로 옮겨간다
- **v1 디코더는 그대로 있다.** v1 시절에 만들어진 코드를 테스트에 문자열로 박아
  고정했다 (`V1_CPU_MB`). 이 상수는 바뀌지 않는다
- v1 코드를 읽으면 `cooler` 키 자체가 없다. 없는 값을 지어내지 않는다
- 인코더는 언제나 최신 버전으로만 쓴다. v1로 되돌려 쓸 일은 없다
- 디코더에 **모르는 비트 검사**를 추가했다. 마스크에 그 버전이 쓰지 않는 비트가
  서 있으면 `null`이다. 절반만 읽고 넘기면 엉뚱한 부품이 나간다

`localStorage`는 공유 코드만 저장하므로 (§8A.3) 저장 포맷 변경이 필요 없었다.
저장해둔 v1 견적은 그대로 열린다.
