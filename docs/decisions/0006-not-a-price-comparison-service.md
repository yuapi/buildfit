# ADR-0006: 가격 비교 커머스로 경쟁하지 않는다

## 상태
채택. **일부 대체됨(ADR-0022)** — 「가격을 다루되 이렇게만 다룬다」와 대안 표의
「가격을 아예 다루지 않기」 탈락 판단은 더 이상 유효하지 않다. 가격을 다루지 않는다

## 배경

PC 견적 도구를 만든다고 하면 가장 먼저 떠오르는 형태가 가격 비교다. 다나와·에누리가
그 영역을 이미 차지하고 있고, 사용자도 견적 도구에 최저가를 기대한다.

문제는 그 시장에서 **개인이 경쟁할 수 없다**는 점이다. (`pc-builder-spec.md` §1.1)
쇼핑몰 제휴, 실시간 가격 수집 인프라, 재고 연동은 전부 규모의 게임이다.

반면 경쟁 도구가 약한 지점이 명확히 있다. (§2)

- 한국 누진세 기반 전기요금 — 해외 도구는 kWh 단가를 곱할 뿐이고 다나와 견적은
  아예 다루지 않는다
- 호환성 규칙의 깊이 — 업계 표준 도구조차 물리적 간섭 검증이 약하다. 포럼에
  "부품이 이 케이스에 들어가는지 계산해달라"는 요구가 올라와 있다 (§5.7.2)
- 견적 단위 성능 비교 — 부품 대 부품 비교 도구는 여럿이지만 완성된 견적끼리
  비교하는 곳은 없다 (§2.3)

## 결정

**가격 비교 커머스로 경쟁하지 않는다.** 이 도구의 정의는
**"이 조합, 문제 없나?"에 답하는 것**이지 "어디가 제일 싼가"에 답하는 것이 아니다.

**하지 않는 것** (§1.1)

- 가격 비교 커머스
- 쇼핑몰 제휴 기반 최저가 나열
- 부품 판매 또는 중개

**가격을 다루되 이렇게만 다룬다** (§7.4)

- "대략 이 정도" 수준으로만. **정확한 최저가를 표방하지 않는다**
- 수집 시각을 반드시 함께 표시
- 구매 링크는 제공하되 **최저가 순위를 매기지 않는다**
- 대표가는 중앙값으로 산출한다 (평균은 이상치에 취약)

가격 연동은 **Phase 2**다. MVP(Phase 0)에는 가격이 들어가지 않는다. (§3)

## 이유

- **이길 수 없는 싸움을 피한다.** 개인 프로젝트가 다나와의 가격 수집 인프라와
  제휴 네트워크를 따라잡을 방법이 없다
- **차별점이 이미 명확하다.** §2의 세 가지는 경쟁 도구가 비워둔 자리이고, 그중
  전기요금은 데이터만 확보하면 바로 구현 가능한 최우선 차별점이다
- **가격은 호환성 판정의 전제가 아니다.** 소켓이 맞는지, GPU가 케이스에 들어가는지는
  가격과 무관하다. 가격 없이도 도구가 완결된다
- **제휴 수익 모델은 판단을 왜곡한다.** "판단을 돕는 도구"라고 하면서 최저가 순위를
  매기면 순위가 곧 수익이 되고, 추천의 중립성을 의심받는다. 수익화는 트래픽 확보
  후로 미룬다 (§12)
- **가격 표시에는 약관 리스크가 있다.** 네이버 오픈 API의 데이터 저장·재가공 허용
  범위가 미확인 상태다. 가격을 핵심 기능으로 두면 이 리스크가 서비스 전체의
  리스크가 된다
- **기능 단위 비활성화에 유리하다.** 가격 표시를 꺼도 호환성·전력은 정상 동작한다.
  `pipeline-plan.md` §6.3 시도 3단계(기능 비활성화)의 feature flag 설계와 맞는다 (§10.3)

**검토한 대안**

| 대안 | 탈락 이유 |
|---|---|
| 최저가 비교를 핵심 기능으로 | 다나와·에누리와 정면 경쟁. 개인이 감당 불가 |
| 제휴 링크 기반 수익화를 초기부터 | 추천 중립성이 의심받고, 트래픽 없는 초기에는 수익도 안 난다 |
| 가격을 아예 다루지 않기 | 총소유비용 비교(§2.1)와 차액 사용처 제안(§6.4)이 성립하지 않는다. 참고값 수준은 필요하다 |

## 결과

**제약**

- **MVP에 가격이 없다.** 사용자가 기대하는 기능 하나가 초기에 빠진 상태로 출시된다.
  호환성·전력·전기요금만으로 방문 가치를 만들어야 한다
- 가격 표시는 항상 "참고값 + 수집 시각" 형태다. 정확도를 주장하지 않으므로 UI 문구와
  면책 표기가 필요하다
- 수익화 시점이 미정이다. 트래픽 확보 후로 미룬다
- 가격을 다루는 순간 상품명 정규화 문제가 따라온다 (§7). 이것이 Phase 2의 실질적
  난관이며, **정규화 정확도가 이 기능의 핵심 메트릭**이다. 수동 검증한 정답 세트
  대비 정확도가 임계 이하면 배포를 차단한다 (§10.4)

**후속 작업**

- `[확인 필요]` 네이버 오픈 API 이용약관상 데이터 저장·재가공 허용 범위
- 가격 표시 UI 문구 확정 ("대략 이 정도", 수집 시각, 순위 없음)
- Phase 2 진입 전 정규화 정확도 기준선 수치 확정
