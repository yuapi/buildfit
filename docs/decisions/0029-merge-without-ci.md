# ADR-0029: CI를 쓸 수 없을 때 로컬 검증으로 머지한다

## 상태
채택 (2026-10-21). ADR-0024의 「PR의 CI가 녹색일 때 머지한다」에 예외 경로를 더한다.

## 배경

머지 규칙은 「CI 녹색일 때」 하나다. 그러면 **CI가 돌지 못하면 아무것도 머지되지 않고, 배포도 멈춘다.**
GitHub Actions가 멈추는 경우:

- 계정의 Actions 사용량·결제 한도 소진, 결제 실패로 인한 잠금 — 작업이 「시작되지 않았다」는 주석만 남긴다
- 러너를 받지 못해 대기열에 멈춤, GitHub 장애
- 레포·계정에서 Actions가 꺼짐 — 실행이 아예 생기지 않는다

이 레포는 public이라 표준 러너 사용량이 과금되지 않는다. 하지만 결제 잠금·장애·비활성화는 그와 상관없이 일어난다.
같은 계정의 private 레포가 한도를 다 쓰면 계정 단위 잠금이 이 레포에도 걸릴 수 있다.

**배포는 CI에 묶여 있지 않다** (ADR-0027). 서버 타이머가 `main`을 당겨 빌드하고, 헬스 체크에 실패하면
되돌린다. 막히는 곳은 머지 하나다.

## 결정

`scripts/merge-gate.sh <PR>`로 머지한다. 사람이든 autopilot이든 같다.

| CI 상태 (`scripts/ci-gate.mjs`) | 처리 |
|---|---|
| 통과 | 머지 |
| **실패** — 검사 단계가 실제로 돌아 깨짐 | **머지하지 않는다.** 로컬로 우회하지 않는다 |
| 도는 중 | 기다린다 (최대 40분, 넘으면 쓸 수 없음으로 본다) |
| **쓸 수 없음** — 결제·사용량 주석, `startup_failure`, 단계 0개로 끝남, 대기열 30분, 실행 없음 10분 | 로컬 검증 → 통과하면 결과를 PR 댓글로 남기고 머지 |

### 로컬 검증 (`scripts/verify-local.sh`)
- **명령을 따로 적지 않는다.** `ci.yml`의 `run:` 줄을 읽어 그대로 돈다. 테스트가 둘이 같은지 고정한다
- 깨끗한 worktree, 1회용 PostgreSQL 16(임시 폴더·빈 포트 55432~, sudo 불필요), 빈 DB, `CI=true`
- **운영 DB(5432)를 쓰지 않는다**
- PR의 head가 아니라 **base에 머지한 결과**를 검사한다. CI의 `pull_request` 실행과 같다
- 로케일을 CI 이미지(`en_US.utf8`)에 맞춘다. 없으면 `C.UTF-8`. **`C`에서는 검색 생성 컬럼 테스트가 깨졌다** —
  `lower()`가 비ASCII 글자를 다르게 다룬다

### 훈련
`CI_GATE_DRILL=1`이면 CI가 통과해도 「쓸 수 없음」 경로를 탄다. 우회 경로가 썩지 않았는지 평소에 확인한다.
첫 훈련은 이 ADR의 PR(이슈 #139)로 했다.

## 검토한 대안

| 대안 | 탈락 이유 |
|---|---|
| 서버에 자체 러너 | public 레포라 포크 PR이 서버에서 코드를 돌릴 수 있다 (ADR-0027) |
| CI 실패도 로컬 통과면 머지 | 깨진 코드를 환경 탓으로 넘긴다. 실패는 실패다 |
| 로컬 검증 명령을 스크립트에 따로 적기 | 두 벌이 되면 한쪽만 고친다 |
| CI 없이 `main`에 바로 push | PR 기록(ADR-0024)이 사라진다. 머지는 여전히 PR로 한다 — API는 Actions와 따로 돈다 |

## 결과
- 로컬 검증으로 머지한 PR에는 「로컬 검증으로 머지 (ADR-0029)」 댓글이 남는다. 나중에 CI가 돌아오면 그 커밋을 다시 돌려 본다
- `ci.yml`에 여러 줄 `run: |`을 쓰면 `verify-local.sh`가 멈춘다. 한 줄로 쓰거나 스크립트를 고친다
- GitHub API 자체가 안 되면(`gh`가 닿지 않음) 머지도 하지 않는다. 그때는 PR을 만들 수도 없다
