# 스스로 모순인 메모리 레코드

조사일: 2026-09-23. 대상: 적재된 카탈로그 RAM 4,876건 (BuildCores OpenDB). 이슈 #20.

## 1. 무엇을 보는가

메모리 키트의 세 값은 서로 묶여 있다.

```
모듈 수 × 모듈 용량 = 총 용량
```

이름에도 같은 사실이 `(2x16GB)`로 적혀 있다. 넷 중 하나라도 어긋나면 **어딘가 틀렸다.**
정답은 몰라도 된다 — 모순이라는 사실만으로 충분하다. #18(출시 연도)과 달리
**경계값이 없다.**

## 2. 결과

| G.Skill Ripjaws M5 RGB DDR5-6000 CL30 64GB (2x32GB) White | 2 | 32 | **32** |
| PNY XLR8 Gaming Black DDR5-5600 CL46 32GB (2x16GB) | 2 | **32** | 32 |

| Silicon Power DDR5 32GB (2x16GB) Zenith RGB 5600MHz CL40 | **1** | **32** | 32 |

| Silicon Power DDR4 8GB (1x8GB) Zenith 3200MHz CL16 | 1 | 8 | **16** |

9건 · 27값. 굵은 것은 이름과 맞지 않는 값이다 — **이름이 맞다고 가정한 표기일
뿐이다.** 코드는 어느 값이 틀렸는지 고르지 않는다.

규칙 3(모듈 수 ≤ 슬롯, **오류 등급**)과 규칙 16(총 용량 ≤ 보드·CPU 최대)이 이 값을
읽는다. 전력 추정도 모듈 수를 쓴다.

## 3. 이름을 어디까지 읽는가

`(NxMGB)` 꼴만 읽는다 — 4,876건 중 4,830건. 나머지 중 8건은 `(24x2)`·`(16x1)`처럼
단위가 없다. KINGBANK가 용량을 앞에 쓰므로 **순서를 알 수 없어** 읽지 않는다.
그때는 산술만 본다.

## 4. 무엇을 하는가

- 값을 고치지 않는다. 판정을 바꾸지 않는다 (ADR-0021)
- 세 값에 모두 `disputed`를 세운다 — 규칙 결과에 「검증 중인 값으로 판정했습니다」
- `/admin`에 이름과 세 값을 나란히 보인다
- 사람이 출처와 함께 확인한 행에는 세우지 않는다 (#19). 셋 다 확인했는데 이름과
  다르면 목록에서도 뺀다 — 이름은 고칠 수 없으니 이름이 틀린 것이다
- 업스트림이 고치면 다음 적재의 거두기가 걷는다

적재의 자기 검사는 `selfCheckFlagsSelect` 하나에 모인다(#18·#20). 중복 불일치 검사의
거두기가 그것을 뺀다 — 검사가 늘 때 한 곳만 고치면 된다.
