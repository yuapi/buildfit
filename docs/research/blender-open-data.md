# Blender Open Data — Phase 3의 첫 벤치마크 시드

조사일: 2026-09-24. 명세 §6.8은 「시드 데이터가 없으면 Phase 3 자체가 성립하지 않는다」고
적고 `[확인 필요: 벤치마크 수치 인용 가능 범위]`를 남겼다. OpenDB에는 벤치마크 필드가 없다
(같은 날 확인). 라이선스가 깨끗한 공개 벤치마크를 찾은 기록이다.

## 1. 결론

**Blender Open Data는 인용 범위 문제가 없다 — 결과 전체가 CC0(퍼블릭 도메인)이다.**
매일 전체 스냅숏을 내려받을 수 있고, CPU·GPU 모두 있다. 다만 **한 용도(3D 렌더링)의 축
하나**다. 게임 FPS를 대신하지 않는다 — 명세 §6.1의 「용도 × 해상도 축」 중 한 칸을 채운다.

## 2. 출처와 라이선스

- 플랫폼: <https://opendata.blender.org/> — Blender Foundation이 운영. 사용자가 공식 벤치마크
  프로그램을 돌려 결과를 올린다
- 스냅숏: <https://opendata.blender.org/snapshots/opendata-latest.zip> (2026-09-24 기준 압축 101MB,
  풀면 1.9GB JSONL). 다운로드 페이지: "The data in this archive is licensed under the CC0 -
  Creative Commons Zero license"
- 아카이브 안 `LICENSE.txt`가 CC0 1.0 Universal 전문이다

## 3. 데이터 모양

한 줄이 벤치마크 실행 한 번이다. `data`에 장면마다 결과가 있다.

| 필드 | 뜻 |
|---|---|
| `blender_version.version` | 벤치마크를 돌린 Blender 버전. **버전마다 점수가 다르다** — 섞지 않는다 |
| `device_info.device_type` | `CPU` · `OPTIX` · `CUDA` · `HIP` · `ONEAPI` · `METAL` |
| `device_info.compute_devices[].name` | 장치 이름 (`NVIDIA GeForce RTX 4070`, `AMD Ryzen 7 9700X 8-Core Processor`) |
| `scene.label` | `monster` · `junkshop` · `classroom` (3.x 이후 표준 세 장면) |
| `stats.samples_per_minute` | 장면 점수 |

**장치 점수 = 세 장면의 분당 샘플 수 합.** Blender Open Data 사이트가 쓰는 정의와 같다.

## 4. 집계 방법

1. **한 버전만 쓴다 — Blender 4.5 LTS.** 실행이 가장 많다(45,297회). 버전을 섞으면 같은 장치도
   점수가 달라진다
2. 세 장면이 모두 있는 실행만, **장치가 하나인 실행만** (여러 GPU 합산 실행은 뺀다)
3. 장치 × 연산 방식마다 **중앙값**. 사용자가 올린 값이라 시스템이 제각각이다 — 평균은 이상치에 약하다
4. **GPU는 실행이 가장 많은 연산 방식**을 쓴다 — NVIDIA는 OptiX, AMD는 HIP, Intel은 oneAPI가 된다.
   같은 카드도 방식마다 점수가 크게 다르다 (RTX 4070: OptiX 5,219 · CUDA 3,292). 화면에 방식을 적는다
5. **실행 5회 미만은 쓰지 않는다**

## 5. 카탈로그와 맞추기

이름을 정규화해 **정확히 같은 것만** 잇는다. 상표(®·™), `N-Core Processor`, `CPU @ 2.80GHz`,
`with Radeon Graphics`, 제조사·브랜드 낱말(NVIDIA·GeForce·Radeon·Intel·AMD), 비영숫자를 걷어낸다.
**비슷한 것으로 잇지 않는다** — 틀린 장치의 점수가 붙는 것이 없는 것보다 나쁘다.

| 대상 (대표 레코드) | 맞은 것 | 5회 이상 |
|---|---|---|
| CPU, 2020년 이후 207개 | 108 (52%) | 91 |
| CPU 전체 511개 | 144 | 67 |
| GPU 칩(`chipset`) 276종 | 138 (50%) | 103 |

GPU는 **칩 단위**다. 같은 칩의 AIB 모델(클럭·쿨러 차이)은 같은 값을 받는다 — 그 차이는 이
데이터로 가를 수 없고, 화면이 「칩 기준 측정」이라고 적는다.

예 (Blender 4.5, 중앙값, 실행 수):

| 장치 | 방식 | 점수 | 실행 |
|---|---|---|---|
| RTX 4090 | OptiX | 11,062 | 526 |
| RTX 4070 | OptiX | 5,219 | 262 |
| RX 7900 XTX | HIP | 4,337 | 218 |
| RX 9070 XT | HIP | 3,279 | 676 |
| Arc B580 | oneAPI | 2,373 | 124 |
| RTX 3060 | OptiX | 2,155 | 630 |
| Ryzen 7 9700X | CPU | 309 | 439 |

## 6. 한계 — 화면이 말해야 하는 것

- **3D 렌더링(Cycles) 하나의 용도다.** 게임 성능이 아니다. 「이 견적은 몇 점」으로 쓰지 않는다 (ADR-0004)
- **사용자 제출 값이다.** 오버클럭·드라이버·전력 설정이 섞인다. 그래서 중앙값과 실행 수를 함께 낸다
- **CPU 점수와 GPU 점수는 같은 눈금이 아니다.** 같은 장면이지만 연산 방식이 달라 CPU 309와
  GPU 5,219를 나란히 비교하지 않는다 — 같은 종류끼리만 비교한다
- 버전이 오르면 다시 집계한다. 스냅숏 날짜를 함께 저장한다

## 7. 명세에 주는 영향

- §6.8의 `[확인 필요: 벤치마크 수치 인용 가능 범위]` — **이 출처는 해소**(CC0). 다른 출처는 여전히 확인 필요
- 게임 FPS 축은 여전히 시드가 없다 — Phase 3의 병목 분석(§6.2)·견적 비교(§6.3)는 이것만으로 성립하지 않는다
- 먼저 할 수 있는 것: **부품·비교 페이지에 「3D 렌더링 측정값」** — 부품 하나의 사실을 출처와 함께 싣는 것이라
  조합 예측이 필요 없다
