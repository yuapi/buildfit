# 견적서 한 줄에서 부품 찾기 — 실측

조사일: 2026-09-21. 대상: 적재된 카탈로그 22,962건 (BuildCores OpenDB).
관련 결정: ADR-0018. 재측정: `npm run measure:quote --workspace @buildfit/ingest`

## 1. 무엇을 재려 했나

국내 사용자는 조립 PC 견적서를 받아 들고 온다. 일곱 칸을 손으로 채우는 대신
그 글을 붙여넣어 검증할 수 있어야 한다. 그러려면 **줄 하나에서 부품 하나를
찾아내야** 한다.

문제는 견적서의 줄이 카탈로그의 이름과 다르다는 것이다.

```
카탈로그  AMD Ryzen 7 9800X3D
견적서    CPU: AMD 라이젠7-5세대 9800X3D (그래니트릿지) (멀티팩)
```

## 2. 실제 견적서를 볼 수 없다

**이 환경에서 국내 쇼핑몰이 전부 차단돼 있다.** 그래서 견적서를 지어내지 않고,
**카탈로그의 진짜 이름을 출발점으로** 삼았다.

진짜 이름에 **우리가 아는 변형만** 가한다.

| 변형 | 근거 |
|---|---|
| ™·®를 지운다 | 카탈로그에 155건 있는데 판매 페이지에는 없다 (`korean-search-terms.md` §3.3) |
| 제품군·제조사를 한글로 | 우리 사전(`KO_ALIASES`)에 있는 표기로만 |
| 제조사를 앞에 붙인다 | 국내 목록의 관행 |
| 유통·포장 표기를 붙인다 | (정품)·멀티팩·병행수입·벌크·대원씨티에스·(신제품) |
| 하이픈 주변 띄어쓰기를 흔든다 | `B650M-A` ↔ `B650M A` |

> **수치를 읽는 법 (2026-09-22 고침).** 전에 「상한이 아니라 하한 근처로
> 읽는다」고 적어 두었는데 **방향이 거꾸로였다.** 확정률에 대해서는
> **상한**으로 읽어야 한다 — §2.1이 근거다. 정확한 수치가 필요해지면 실제
> 견적서를 구해 다시 잰다.
>
> 단일 오답 수치는 반대다. 변형이 더하면 오답도 더 날 수 있으므로 **하한**이다.

### 2.1 ★ 출발점이 카탈로그 이름이라 확정률이 부풀려진다

이 측정은 **카탈로그의 전체 이름**에서 시작한다. 전체 이름은 그 자체로 SKU
하나를 가리킨다 — `Noctua NH-D15 Air 168mm G2 LBC 91.58 CFM Brown / Silver`.
거기에 표기 변형을 얹어도 **가리키는 대상은 여전히 하나다.**

실제 견적서 줄은 대개 그보다 짧다. 「쿨러: 녹투아 NH-D15」는 카탈로그의
NH-D15 계열 여럿을 동시에 가리킨다. **줄이 SKU를 특정하지 못하는 것은 매칭의
실패가 아니라 줄의 성질이다.** 그런데 확정률은 그 둘을 한 수치로 섞는다.

손으로 쓴 국내 견적서 풍 8줄로 대조해 봤다 (**이것도 추측이다** — 실제
견적서를 볼 수 없다).

| 줄 | 결과 |
|---|---|
| `CPU: AMD 라이젠7 9800X3D (정품)` | 확정 |
| `메인보드: MSI MAG B650 TOMAHAWK WIFI` | 확정 |
| `파워: 커세어 RM850x 2024` | 확정 |
| `메모리: 지스킬 트라이던트Z5 DDR5-6000 32GB (2x16GB)` | 6개 |
| `그래픽카드: MSI 지포스 RTX 5080 16G 게이밍 트리오` | 6개 |
| `케이스: 리안리 O11 Dynamic EVO` | 6개 |
| `쿨러: 녹투아 NH-D15` | 6개 |
| `SSD: 삼성전자 990 PRO 1TB` | 2개 |

**확정 3/8 · 못 찾음 0.** 확정률은 §3의 72.6%보다 한참 낮고, n=8이라 수치로
쓸 것은 아니다. 읽을 것은 방향과 이유다.

- 여럿으로 갈린 다섯 줄은 **색상·클럭·리비전 차이**다. `NH-D15`도 `O11
  Dynamic EVO`도 카탈로그에 계열이 여럿 있고, 그 줄만으로는 어느 것인지 알 수
  없다. **우리가 모르는 것이 맞다**
- **못 찾음이 0이다.** 부품을 잃지 않았다 — 고를 목록이 짧아진 것이다.
  손으로 일곱 칸을 채우는 것과 비교할 대상은 확정률만이 아니다

그래서 §3의 확정률은 **매칭기의 상한**으로 읽는다. 사용자에게 실제로 남는
일은 「짧은 목록에서 고르기」이고, 그쪽 수치(여럿일 때 평균 2.7개)가 체감에
더 가깝다.

표본: 7개 카테고리 × 60건 = **420건**. 2023년 이후 출시분. 표본 추출은
`order by md5(id::text)`라 되풀이해도 같은 표본이 나온다.

## 3. 결과

| | 짧은 조각 **버림** | 짧은 조각 **붙임** |
|---|---:|---:|
| 하나로 확정 | 253 (60.2%) | **293 (69.8%)** |
| 여럿, 정답 포함 | 166 (39.5%) | 127 (30.2%) |
| └ 여럿일 때 평균 | 3.8개 | **2.7개** |
| 못 찾음 | 0 (0.0%) | 0 (0.0%) |
| **★ 단일 오답** | **0** | **0** |
| 여럿, 정답 없음 | 1 (0.2%) | 0 (0.0%) |

### 3.1 ★ 단일 오답이 0이라는 것

가장 중요한 수치다. **"이것입니다"라고 하나를 확정한 293건이 전부 맞았다.**

여럿이면 고르게 하면 되고 못 찾으면 못 찾았다고 하면 되지만, **하나를 잘못
확정하면 사용자는 확인 없이 틀린 부품을 견적에 넣는다.** 그리고 그 위에서 돌아간
호환성 판정은 아무 의미가 없어진다.

이 수가 0이 아니게 되면 기능을 손봐야 한다. 테스트가 아니라 이 실측이 그 경보다.

### 3.2 짧은 조각을 붙이는 쪽이 낫다

`Ti`·`OC`·`i5`·`A` 같은 두 글자 이하 조각을 어떻게 다룰지가 갈림길이었다.

혼자 두면 못 쓴다. 구분자를 지우고 나면 `ti`는 `Edition`·`Multi` 안에도 있어서,
4070 Ti를 찾으려다 `RTX 4070 EVO OC Edition`이 섞여 나온다 (ADR-0017 §1).

**앞 조각에 붙이면 반대로 정확해진다.**

```
RTX 4070 Ti              → rtx4070ti          ⊂ rtx4070tisuper…     ✅
RTX 4070 EVO OC Edition  → rtx4070evoocedition ⊅ rtx4070ti          ✅
```

붙이는 쪽이 확정률이 9.6%p 높고, 여럿일 때 평균 개수도 3.8 → 2.7로 준다.
어느 쪽이든 단일 오답은 0이므로 **안전을 잃지 않고 얻는 개선**이다.

### 3.3 붙이는 데는 선이 있다

구현 중에 두 번 틀렸고, 둘 다 실측 이전에 손으로 만든 줄에서 드러났다.

| 틀린 것 | 왜 | 고친 방법 |
|---|---|---|
| `라이젠7-5세대` → `ryzen75` | `7`을 붙인 뒤 `5`까지 붙었다 | 한 조각에 **한 번만** 붙인다 |
| `RTX 5080 게이밍 트리오 OC` → `5080oc` | 사이의 「게이밍」·「트리오」를 버린 뒤라 `5080`이 여전히 "바로 앞"이었다 | **바로 앞 덩어리**가 조각이 됐을 때만 붙인다 |

두 번째가 중요하다. 버린 말도 자리를 차지한다.

## 4. 그 밖에 드러난 것

### 4.1 줄 앞 이름표를 찾는 말로 쓰면 안 된다

```
CPU: AMD 라이젠7 9800X3D
```

`CPU`를 검색 조각으로 쓰면 **이름에 `cpu`가 든 부품**만 찾게 된다.
9800X3D 줄이 실제로 0건이 났다.

이름표는 찾는 말이 아니라 **어디서 찾을지**를 말한다. 카테고리로 쓰면
줄이 살아날 뿐 아니라 범위도 좁아진다.

**구분자가 있어야 이름표로 본다** (`CPU:` `[CPU]` `CPU -` `CPU |`).
구분자 없이 앞 낱말만 보면 `Corsair …`의 첫 낱말도 이름표가 된다.

### 4.2 다루지 않는 부품은 "못 찾음"과 다르다

```
SSD: 삼성 990 PRO 2TB   → 스토리지는 아직 다루지 않습니다
메모리: 삼성 DDR5-5600   → 찾지 못했습니다 (찾은 말: samsung ddr5 5600 16gb)
```

사용자가 할 행동이 다르다. "못 찾았다"는 다시 쳐보게 만들지만
"아직 다루지 않는다"는 그렇지 않다. 그래서 이름표 사전에 **취급하지 않는
카테고리도** 적어둔다 — SSD·모니터·키보드·운영체제.

그리고 그런 줄은 **찾지 않는다.** 「SSD: 삼성 990 PRO」로 삼성 메모리를
부를 이유가 없다.

### 4.3 글자가 없는 줄은 부품 줄이 아니다

```
합계 2,480,000원  →  조각: 480, 000
```

숫자만 남은 조각으로 찾으면 엉뚱한 부품이 줄줄이 나온다. 실제로 이 줄이
AMD EPYC과 ASUS 케이스를 불렀다.

**부품 이름에는 반드시 글자가 있다.** 글자가 든 조각이 하나도 없으면
부품 줄로 보지 않는다.

### 4.4 검색창의 "타이핑 중" 규칙을 그대로 쓰면 안 된다

ADR-0017은 타이핑 중인 한글을 앞부분 일치로 받는다 — 「라이」가 「라이젠」이 된다.
그 규칙을 견적서에 쓰면 **「개」가 「갤럭시」로 잡힌다** (받침만 다르다).
실제로 "수량 1개"가 GALAX 그래픽카드를 불렀다.

견적서는 **다 쓴 글**이다. 사전 표기가 정확히 맞을 때만 받는다.

## 5. 속도

한 줄에 쿼리 하나다. trigram 인덱스(ADR-0017 §2) 덕에 줄당 2~5ms이고,
11줄짜리 견적서가 **31ms**였다. 상한은 40줄이다.

## 6. 다시 재야 할 때

- **실제 견적서를 구하면 다시 잰다.** §2의 변형 목록이 추측이 아니게 된다
- 카탈로그가 커지면 다시 잰다. 후보가 늘면 확정률이 떨어진다
- 사전(`KO_ALIASES`)에 말을 더하면 다시 잰다
- **단일 오답이 0이 아니게 되면 멈춘다.** 그게 이 기능의 전제다
