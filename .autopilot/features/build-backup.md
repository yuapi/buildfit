# 기능: 저장한 견적 내보내기·가져오기

근거: `docs/pc-builder-spec.md` §8A.3 — 「견적 목록 전체를 JSON으로 내보내기/가져오기 (Phase 1)」.
Phase 1의 명세 항목인데 구현이 없다 (2026-10-01 발굴, `apps/web/src`에 다운로드·파일 읽기 코드 0).

## 목적

저장한 견적(`builds`, 최대 20개)은 이 브라우저에만 있다. 브라우저를 바꾸거나 데이터를 지우면
사라지고, 지금 백업 수단은 견적마다 공유 링크를 하나씩 복사하는 것뿐이다. 목록 전체를
파일 하나로 옮길 수 있게 한다. **서버로 보내지 않는다** — 파일은 사용자 기기에서 만들고 읽는다.

## 인터페이스

- 저장 목록(`SaveBox`) 아래 「목록 내보내기」 — `buildfit-견적-YYYY-MM-DD.json` 다운로드
- 「가져오기」 — 파일 선택. 결과를 한 줄로 알린다: 「3개를 더했습니다. 1개는 이미 있고, 1개는 읽을 수 없어 건너뛰었습니다.」

## 파일 형식

```json
{ "app": "buildfit", "kind": "saved-builds", "v": 1, "exportedAt": "…", "builds": [SavedBuild, …] }
```

- `builds`의 항목은 localStorage의 `SavedBuild` 그대로다 — 형식을 두 벌 두지 않는다
- **add-only** (CLAUDE.md 절대 규칙). 파일은 사용자 손에 남으므로 브라우저 저장소와 같은 규칙을 따른다

## 가져오기 규칙

1. 항목마다 `migrateSavedBuild`를 거친다 — 코드가 안 읽히면 버린다 (기존 읽기 규칙과 같다)
2. 같은 `code`가 이미 있으면 **기존 것을 둔다** (이름을 덮지 않는다 — 사용자가 이 브라우저에서 고친 이름일 수 있다)
3. **지금 있는 견적은 하나도 빼지 않는다.** 남은 자리(`LIMITS.builds` − 지금 수)만큼 파일의 것을 최신순으로 넣고,
   못 넣은 수를 알린다 — 조용히 버리지 않는다. 결과 목록은 `savedAt` 최신순
   - (T-11에서 바꿈) 처음 설계는 「합친 전체를 최신순으로 잘라 20개」였다. 그러면 파일 쪽이 더 최신일 때
     **가져오기가 이 브라우저의 견적을 지운다.** 변이 시험으로 확인했다
4. 파일이 형식에 안 맞으면(JSON 아님, `app`·`kind` 다름, `builds`가 배열 아님) 아무것도 바꾸지 않고 그렇다고 말한다
