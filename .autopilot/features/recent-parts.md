# 기능: 최근 본 부품

근거: `docs/pc-builder-spec.md` §8A.1 — 저장 대상 표의 `recent_parts`(최근 조회한 부품, 20개).
저장 함수(`recordRecentPart`·`loadRecentParts`)와 마이그레이션·테스트는 있는데 **부르는 곳이 0이다**
(2026-10-02 발굴). 아무것도 기록하지 않고 아무것도 보여주지 않는다.

## 목적

부품 페이지에서 스펙을 보고 견적 도구로 돌아가면, 방금 본 부품을 다시 검색해야 한다.
본 것을 기억해 두었다가 다시 고를 수 있게 한다. 이 브라우저에만 남고 서버로 가지 않는다.

## 데이터

`RecentPart`에 **`slug`를 더한다** (add-only — 선택 필드). 없으면 부품 페이지로 이을 수 없다.
지금까지 기록된 레코드는 0이지만 규칙대로, `slug`가 없는 레코드는 링크 없이 둔다.

## 단계

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1/2 ✅ | 부품 상세 페이지가 본 것을 기록(클라이언트 조각) + `/part`에 「최근 본 부품」(이 브라우저 것, 최신순, 링크) + 저장소 스냅샷에 `recentParts` | storage 테스트(slug 왕복, 스냅샷), Playwright: 두 부품을 본 뒤 `/part`에 최신순으로 나오고, 저장 불가 브라우저에선 칸이 없다 |
| 2/2 ✅ | 견적 도구의 고르기 목록이 검색어가 비었을 때 **그 칸 카테고리의 최근 본 부품**을 위에 보여준다. **지금 견적과 안 맞는 것은 거른다** — 고를 때 거르기(ADR-0016)를 비껴가면 안 된다. 서버가 id 목록을 같은 제약으로 거른다 | 거르기 SQL 테스트 + Playwright(본 CPU가 고르기 맨 위, 안 맞는 소켓은 빠짐) + README 반영 |

## 완료 (2026-10-02)

두 단계 끝. 고르기 목록은 검색어가 비었을 때 그 칸의 최근 본 부품 5개까지를 검색창 아래에 둔다 —
listbox 밖의 버튼이라 방향키 탐색(aria-activedescendant)을 건드리지 않는다. 거르기는 서버의
`pickableAmong`이 검색과 **같은 `constraintWhere`**로 한다 (거르는 규칙이 두 벌이 되지 않게).
